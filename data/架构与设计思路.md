# iceberg-data 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-data` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-data` 是一个**可选模块**，为 **JVM 应用提供直接读写 Iceberg 表的通用支持**，无需依赖特定计算引擎（Spark/Flink）。它面向希望在自己的 Java 应用中读取或迁移 Iceberg 数据的场景，是连接 `iceberg-api`/`iceberg-core` 与“无引擎 JVM 应用”之间的便利层。

## 2. 模块组成

| 类 | 职责 |
|---|---|
| `IcebergGenerics` | 读入口：提供链式 `read(Table)` 构建扫描。 |
| `TableScanIterable` | 把扫描任务转为可迭代的记录流。 |
| `GenericReader` | 通用读取器：打开文件、应用投影与残留过滤、合并任务。 |
| `GenericAppenderFactory` | 写入口工厂：创建数据/删除文件写入器。 |
| `BaseFileWriterFactory` | 写入器工厂基类：配置加密/压缩/格式/Schema 等钩子。 |
| `DeleteFilter` / `GenericDeleteFilter` | 应用等值删除与位置删除，过滤已删记录。 |
| `InternalRecordWrapper` | 把内部记录适配为通用 `Record` 视图。 |
| `TableMigrationUtil` | 辅助把非 Iceberg 表（如 Parquet/ORC 目录）迁移为 Iceberg 表。 |

## 3. 整体架构

```
   应用代码
      │  IcebergGenerics.read(table)  /  GenericAppenderFactory
      ▼
 ┌─────────────────────────────────────────┐
 │              GenericReader              │
 │  扫描任务 → 打开文件 → 投影/残留过滤       │
 └──────────────┬──────────────────────────┘
                │
       ┌────────▼────────┐
       │   DeleteFilter   │ (等值/位置删除合并)
       └────────┬────────┘
                │
       ┌────────▼────────┐
       │ InternalRecord   │ → Generic Record
       │ Wrapper          │
       └─────────────────┘
                ▲
   写路径：BaseFileWriterFactory → DataWriter/DeleteWriter
   迁移路径：TableMigrationUtil（外部表 → Iceberg）
```

## 4. 核心设计思想

### 4.1 引擎无关的便利 API
`IcebergGenerics` 提供类似 `read(table).select(...).where(...)` 的链式 API，屏蔽 core 的扫描/任务/读模型细节，让普通 JVM 应用零引擎依赖即可读取 Iceberg。

### 4.2 删除合并
`DeleteFilter` 同时处理等值删除（按字段值匹配）与位置删除（按文件内行号），在读取侧把已删记录过滤掉，向上呈现“当前有效数据”。长函数 `applyEqDeletes`/`applyPosDeletes`/`fileProjection` 体现了删除合并的复杂编排。

### 4.3 投影与残留谓词下推
`GenericReader` 应用列投影（只读需要的列）并把引擎未消费的残留谓词在读取侧应用，减少返回数据量。

### 4.4 写入工厂钩子
`BaseFileWriterFactory` 通过多个 `configure*` 钩子（加密/压缩/格式/Schema/分区）统一数据/删除写入器的构建，子类按格式特化。便于在不同写场景复用。

### 4.5 表迁移支持
`TableMigrationUtil` 列举外部表分区文件、收集指标，支撑把 Parquet/ORC 目录表迁移为 Iceberg 表，降低迁移门槛。

## 5. 上下游依赖关系

- **向上**：面向 JVM 应用直接调用。
- **向下**：依赖 `iceberg-api`/`iceberg-core` 的扫描、读写、删除模型；可按格式依赖 `iceberg-parquet`/`iceberg-orc`/`iceberg-arrow`。
- **横向**：与引擎模块（spark/flink）平行，但更轻量、面向通用 JVM。

## 6. 设计要点总结

1. **引擎无关便利层**：让无引擎 JVM 应用也能读写 Iceberg。
2. **读取侧删除合并**：等值+位置删除统一过滤。
3. **投影/残留下推**：减少 IO。
4. **写入工厂钩子**：统一数据/删除写入器构建。
5. **迁移支持**：外部表→Iceberg 的便捷路径。

# iceberg-common 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-common` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-common` 是 Iceberg 项目中**最底层的公共工具模块**。它不依赖任何 Iceberg 业务模块，仅依赖 relocated guava（`org.apache.iceberg.relocated.com.google.common.*`，由 `bundled-guava` 模块提供）。它被 `api`、`core` 以及所有引擎/云存储集成模块依赖。

在整个分层中，它是“地基中的地基”：提供与 Iceberg 表格式无关的、纯 JVM 反射工具，供上层在不同版本引擎间做兼容性适配。

## 2. 模块组成

本模块仅包含 4 个类，均位于 `org.apache.iceberg.common` 包下，构成 **Dyn\* 动态反射工具系列**：

| 类 | 职责 |
|---|---|
| `DynFields` | 动态字段访问：封装 `java.lang.reflect.Field`，提供 Unbound/Bound/Static 三种视图，支持候选查找。 |
| `DynMethods` | 动态方法调用：封装 `java.lang.reflect.Method`，提供 Unbound/Bound/Static 三种视图，支持候选查找与 NOOP 空对象。 |
| `DynConstructors` | 动态构造函数调用：复用 `DynMethods.UnboundMethod`，封装 `java.lang.reflect.Constructor`。 |
| `DynClasses` | 动态类加载/查找：按候选类名定位 `Class<?>`，是最基础的“类定位”工具。 |

## 3. 整体架构

```
              ┌──────────────────────────────────────┐
              │         上层调用方                     │
              │  (api / core / spark / flink / mr …)  │
              └──────────────────┬───────────────────┘
                                 │ 依赖
              ┌──────────────────▼───────────────────┐
              │          iceberg-common               │
              │  ┌────────────┐  ┌────────────────┐  │
              │  │ DynClasses │→ │ DynConstructors│  │
              │  └────────────┘  └───────┬────────┘  │
              │                          │ 复用       │
              │  ┌────────────┐  ┌───────▼────────┐  │
              │  │ DynFields  │  │  DynMethods    │  │
              │  └────────────┘  └────────────────┘  │
              └──────────────────┬───────────────────┘
                                 │ 依赖
              ┌──────────────────▼───────────────────┐
              │      bundled-guava (relocated)        │
              └──────────────────────────────────────┘
```

- `DynClasses` 定位类 → `DynConstructors`/`DynMethods` 在类上找构造器/方法 → `DynFields` 找字段。
- `DynConstructors` 的 `Ctor` 继承自 `DynMethods.UnboundMethod`，使“构造器调用”与“方法调用”共享同一套调用抽象，这是本模块关键的复用设计。

## 4. 核心设计思想

### 4.1 候选逐个尝试 + 短路（跨版本兼容）
所有 Dyn\* 工具都采用 **Builder + 候选列表** 模式：调用方按优先级注册多个候选（类名/方法名/字段名组合），Builder 仅在尚未命中时才尝试下一个候选，命中即止。这使得 Iceberg 能在**不同版本的 Spark/Flink/Hive** 中透明运行——引擎内部类成员名/位置随版本变化时，只需多注册几个候选即可屏蔽差异。所有失败候选会被收集，最终拼入异常信息，便于排查。

### 4.2 受检 / 非受检双版本终端方法
`buildChecked()` 抛受检异常（`NoSuchFieldException`/`NoSuchMethodException`），`build()` 抛 `RuntimeException`。调用方可根据自身是否愿意处理受检异常选择合适版本。

### 4.3 空对象模式（Null Object）
- `DynFields.AlwaysNull`：永远返回 null 的字段实现，`defaultAlwaysNull()` 时使用，使调用链无需判空。
- `DynMethods.NOOP`：什么都不做、返回 null 的方法实现，`orNoop()` 时使用。

二者让“找不到也无所谓”的场景优雅降级，避免 NPE 与分散的 null 判断。

### 4.4 异常统一包装
反射 API 抛出的受检异常（`IllegalAccessException` 等）被统一包装为 `RuntimeException`（通过 guava `Throwables.propagate`），让上层调用方免于繁琐的 try-catch。

### 4.5 受控访问隐藏成员
`hiddenImpl` 系列方法通过 `getDeclaredField`/`getDeclaredMethod` + `AccessController.doPrivileged(setAccessible(true))` 访问引擎内部的非公开成员，在受控前提下突破访问限制以实现引擎集成。

### 4.6 三种绑定视图
字段/方法均提供：
- **Unbound**：未绑定，需显式传入 target 调用；
- **Bound**：绑定到具体实例，调用时无需再传 target；
- **Static**：静态成员专用视图。

清晰区分实例成员与静态成员的使用语义，避免误用。

## 5. 上下游依赖关系

- **向上**：被 `iceberg-core`、各引擎集成模块（spark/flink/mr 等）广泛用于访问引擎内部类成员。
- **向下**：仅依赖 `bundled-guava` 提供的 relocated guava 工具类（Preconditions/Throwables/Joiner/Sets/Maps 等）。
- **无业务耦合**：不涉及任何 Iceberg 表格式概念（Schema/Snapshot/Manifest 等），是纯粹的基础设施。

## 6. 设计要点总结

1. **基础设施先行**：把跨版本反射适配这一最底层痛点独立成最小模块，避免业务代码与反射细节耦合。
2. **Builder 模式 + 候选短路**：以声明式 API 表达“多版本兼容查找”意图。
3. **空对象模式**：优雅降级，消除 null 判断噪音。
4. **构造器复用方法抽象**：`DynConstructors` 继承 `DynMethods.UnboundMethod`，DRY。
5. **受检/非受检双版本**：兼顾不同调用方的异常处理偏好。

# iceberg-pig 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-pig` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-pig` 是 Iceberg 与 **Apache Pig** 引擎的集成模块，处于 Pig LoadFunc 抽象与 Iceberg 表扫描抽象之间。它向下依赖 `iceberg-api`/`iceberg-core`/`iceberg-common`/`iceberg-parquet`，向上为 Pig 脚本的 `LOAD` 语句提供访问 Iceberg 表的统一入口。

在 Iceberg 整体分层中的位置：

```
        Pig 脚本 (LOAD '...' USING IcebergStorage)
                  │
        ┌─────────▼─────────┐
        │   iceberg-pig     │  ← 本模块：LoadFunc + InputFormat + Parquet 读取器
        │  (Pig 引擎适配层)  │
        └─────────┬─────────┘
                  │
   iceberg-core / iceberg-parquet / iceberg-common
                  │
              iceberg-api
```

核心职责：

- 实现 Pig `LoadFunc` 系列接口，让 Pig 通过 `LOAD` 语句读取 Iceberg 表。
- 把 Iceberg Schema 转换为 Pig `ResourceSchema`，让 Pig frontend 了解表结构。
- 接收 Pig 下推的过滤谓词与投影字段，翻译为 Iceberg `Expression` 并下推到 `TableScan`。
- 把 Iceberg 的 `CombinedScanTask` 包装为 Hadoop `InputSplit`，供 Pig 的 MapReduce 执行引擎调度。
- 把 Parquet 文件读取结果适配为 Pig 数据类型（`Tuple`/`DataBag`/`Map` 等），并注入分区列常量。

## 2. 包结构概览

本模块仅含 4 个类，全部位于 `org.apache.iceberg.pig` 包下：

| 类 | 职责 |
|---|---|
| `IcebergStorage` | Pig `LoadFunc` 入口实现，串联 schema 暴露/谓词下推/投影/表加载 |
| `IcebergPigInputFormat` | MapReduce `InputFormat` 实现，桥接 Pig MR 执行与 Iceberg 表扫描 |
| `PigParquetReader` | Parquet 文件读取结果适配为 Pig 类型的读取器构造器 |
| `SchemaUtil` | Iceberg Schema 与 Pig `ResourceSchema`/`DataType` 的双向转换工具 |

模块结构简单清晰，按"Pig 入口 → MR 适配 → 文件读取 → 类型映射"四层组织。

## 3. 核心类与设计模式

### 3.1 Pig 入口：`IcebergStorage`

继承 Pig `LoadFunc` 并实现 `LoadMetadata`/`LoadPredicatePushdown`/`LoadPushDown` 三个接口，是 Pig 脚本访问 Iceberg 表的统一入口。

**职责矩阵**：

| 接口 | 方法 | 作用 |
|---|---|---|
| `LoadFunc` | `setLocation`/`getInputFormat`/`getNext`/`prepareToRead` | 定位表、构造 InputFormat、产出 Tuple |
| `LoadMetadata` | `getSchema`/`getStatistics`/`getPartitionKeys`/`setPartitionFilter` | 向 Pig frontend 暴露表结构 |
| `LoadPredicatePushdown` | `getPredicateFields`/`getSupportedExpressionTypes`/`setPushdownPredicate` | 接收 Pig 下推的过滤谓词 |
| `LoadPushDown` | `getFeatures`/`pushProjection` | 接收 Pig 下推的投影字段 |

**设计模式**：

- **静态缓存**：`tables`（location → Table）与 `locations`（signature → location）为静态并发 Map，避免重复加载同一表，并支持 location 反查。
- **可插拔 Tables 实现**：通过 `pig.iceberg.tables.impl` 配置自定义 `Tables` 实现，默认 `HadoopTables`，使用 `ReflectionUtils.newInstance` 实例化。
- **谓词翻译独立成方法**：`convert(Expression)` 递归处理二叉/一元/区间/IN 表达式，`convert(OpType, Column, Const)` 处理单列与常量的二元比较，特殊处理 NaN 比较（`isNaN`/`notNaN`）。

**signature 隔离机制**：

Pig 在同一 Job 中可能多次调用同一 UDF（不同实例），通过 `UDFContextSignature` 把每个 `IcebergStorage` 实例的状态（schema/投影/过滤/location）隔离，避免互相覆盖。frontend 阶段把配置序列化进 `UDFContext`，`setLocation` 阶段拷贝到 `Configuration`（key 加 signature 后缀），供 backend InputFormat 读取。

### 3.2 MR 适配：`IcebergPigInputFormat<T>`

继承 Hadoop `InputFormat`，桥接 Pig（Hadoop MR v2 API）与 Iceberg 表扫描抽象。

**`getSplits`**：

1. 若已缓存 splits 则直接返回，避免重复规划。
2. 从 Configuration 反序列化 Pig 下推的过滤表达式，下推到 `TableScan.filter`。
3. 调用 `TableScan.planTasks()` 规划 `CombinedScanTask`，每个包装为 `IcebergSplit`。

**`IcebergSplit`（内部类）**：实现 `Writable`，通过 `SerializationUtil` 把 `CombinedScanTask` 序列化为字节数组传输到 Mapper 端。`getLocations` 返回 `{"*"}` 表示不限定位置。

**`IcebergRecordReader`（内部类）**：逐文件读取 `CombinedScanTask` 内的多个 `FileScanTask`。

**设计模式**：

- **Configuration key 加 scope**：`scope(key)` 方法给 key 加 `.<signature>` 后缀，使同一 Job 内多个 `IcebergStorage` 实例（不同 signature）互不干扰，避免 UDF 上下文串扰。
- **迭代器链**：`nextKeyValue` 在当前文件 reader 耗尽时调用 `advance()` 切换到下一个文件，形成文件间的迭代器链。

### 3.3 分区列注入

`IcebergRecordReader.advance()` 处理分区表的"虚拟列"注入：

1. 从 `PartitionSpec.identitySourceIds` 判断是否有 identity 分区列。
2. 若有：把分区列从 `readSchema` 中剔除（避免重复读），构造 `partitionValueMap`（fieldId → 分区值）。
3. 调用 `PigParquetReader.buildReader` 时传入 `partitionValueMap`，在 struct 阶段用 `ParquetValueReaders.constant` 替换实际读取。
4. `convertPartitionValue` 把 Iceberg 的 `ByteBuffer` 类型分区值转为 Pig 的 `DataByteArray`。

### 3.4 Parquet 读取器构造：`PigParquetReader`

把 Parquet 文件读取结果适配为 Pig 数据类型（`Tuple`/`DataBag`/`Map` 等）的读取器构造器。

**双策略**：

- **`ReadBuilder`**：当 Parquet 文件 schema 含 field id 时，按 id 严格匹配（支持 schema 演化/列重排/列裁剪/分区列注入）。实现 `TypeWithSchemaVisitor`，按 Iceberg schema 与 Parquet type 的对照关系为各类型构造 `ParquetValueReader`。
- **`FallbackReadBuilder`**：当文件 schema 不含 field id 时，按位置回退匹配，保证对老文件的兼容。

**struct 构造的关键逻辑**：

1. 遍历文件 struct 字段，按 id 建立 `readersById`/`typesById`/`maxDefinitionLevelsById` 映射。
2. 遍历 expected schema 字段：若 id 命中 `partitionValues`，用 `constant` 读取器注入分区值；若 id 在 `readersById` 中，按重排顺序取用；否则用 `nulls` 读取器填充。
3. 构造 `TupleReader`，字段顺序对齐 expected schema。

**类型映射**（`primitive` 方法）：

- 有 original type：ENUM/JSON/UTF8 → `StringReader`；DATE → `DateReader`（输出 `yyyy-MM-dd` 字符串）；INT_(8/16/32) 期望 long 时用 `IntAsLongReader`；TIMESTAMP_MILLIS/MICROS → 对应 `TimestampReader`；DECIMAL 按底层 BINARY/INT32/INT64 选择对应 `DecimalReader`。
- 无 original type：BINARY/FIXED → `BytesReader`（输出 `DataByteArray`）；FLOAT 期望 double 走 `FloatAsDoubleReader`；其余基本类型用 `UnboxedReader`。

**自定义 Reader**：

- `DateReader`：把 Parquet DATE（自 epoch 起的天数）读取为 `yyyy-MM-dd` 字符串。
- `BytesReader`：把 Parquet BINARY 读取为 Pig `DataByteArray`。
- `TimestampMicrosReader`/`TimestampMillisReader`：把时间戳读取为 ISO 字符串。
- `MapReader`：把 repeated key-value 读取为 Pig `Map`（底层 `LinkedHashMap` 保持顺序）。
- `ArrayReader`：把 repeated 元素读取为 Pig `DataBag`（每个元素包装为单字段 Tuple，因 Pig bag 元素必须是 Tuple）。
- `TupleReader`：把 struct 各字段读取结果组装为 Pig `Tuple`，按 expected schema 顺序填充。

### 3.5 类型映射：`SchemaUtil`

Iceberg Schema 与 Pig `ResourceSchema`/`DataType` 之间的双向转换工具。

**类型映射表**：

| Iceberg 类型 | Pig DataType |
|---|---|
| BOOLEAN | BOOLEAN |
| INTEGER | INTEGER |
| LONG | LONG |
| FLOAT | FLOAT |
| DOUBLE | DOUBLE |
| TIMESTAMP/DATE/STRING | CHARARRAY |
| FIXED/BINARY | BYTEARRAY |
| DECIMAL | BIGDECIMAL |
| STRUCT | TUPLE |
| LIST | BAG |
| MAP | MAP |

**设计要点**：

- Iceberg 与 Pig 类型系统差异较大（如 timestamp/date 在 Pig 端以 CHARARRAY 表示、list 以 BAG 表示、struct 以 TUPLE 表示），集中做映射避免散落各处。
- list 的元素非 struct 时需包一层 tuple（Pig bag 元素必须是 tuple）。
- map 仅支持 STRING key，遇非 STRING key 抛异常，提前暴露不兼容。
- `project` 方法按字段名列表裁剪出投影后 Schema，保持 `requiredFields` 给定的顺序（Pig 下推的投影字段顺序可能与表 schema 不同）。

## 4. 关键流程

### 4.1 Pig 读取 Iceberg 表

```
Pig 脚本: A = LOAD 'hdfs:///path/to/table' USING org.apache.iceberg.pig.IcebergStorage;
   │
   ▼ frontend 阶段（HiveServer2/编译期）
IcebergStorage.getSchema
   │  - load(location) 加载 Iceberg Table（缓存到 tables map）
   │  - SchemaUtil.convert(schema) -> Pig ResourceSchema
   │  - storeInUDFContext: schema 序列化进 UDFContext
   ▼
IcebergStorage.setPushdownPredicate（若有 WHERE 谓词）
   │  - convert(predicate): Pig Expression -> Iceberg Expression
   │  - storeInUDFContext: filter 序列化进 UDFContext
   ▼
IcebergStorage.pushProjection（若有列裁剪）
   │  - 提取字段别名列表
   │  - storeInUDFContext: projected fields 序列化进 UDFContext
   │
   ▼ backend 阶段（setLocation）
IcebergStorage.setLocation
   │  - locations.put(signature, location)
   │  - copyUDFContextToScopedConfiguration: schema/projection/filter 拷贝到 Configuration（key.signature）
   ▼
IcebergStorage.getInputFormat
   │  - new IcebergPigInputFormat(table, signature)
   ▼
IcebergPigInputFormat.getSplits
   │  - 反序列化 filter 下推到 TableScan
   │  - scan.planTasks() -> CombinedScanTask -> IcebergSplit
   ▼
IcebergPigInputFormat.IcebergRecordReader.initialize / advance / nextKeyValue
   │  - 反序列化 schema 与 projectedFields，计算 projectedSchema
   │  - HadoopInputFile.fromLocation 打开文件
   │  - 分区表: readSchema 剔除分区列，构造 partitionValueMap
   │  - Parquet.read + PigParquetReader.buildReader 构造列读取器
   │  - 文件间迭代，行内迭代产出 Tuple
   ▼
IcebergStorage.getNext -> Pig Tuple
```

### 4.2 谓词下推转换

```
Pig Expression (OP_AND/OR/EQ/NE/NOT/GE/GT/LE/LT/BETWEEN/IN/NULL)
   │
   ▼ IcebergStorage.convert
   │
   ├── BinaryExpression
   │   ├── OP_AND: Expressions.and(convert(lhs), convert(rhs))
   │   ├── OP_OR:  Expressions.or(convert(lhs), convert(rhs))
   │   ├── OP_BETWEEN: and(GE(lower), LE(upper))
   │   ├── OP_IN: 多个 EQ 做 OR 归约
   │   └── 其他: convert(op, Column, Const)
   │
   ├── UnaryExpression
   │   ├── OP_NOT:  Expressions.not(convert(unary))
   │   └── OP_NULL: Expressions.isNull(name)
   │
   └── convert(op, col, constant)
       ├── OP_EQ: NaN ? isNaN : equal
       ├── OP_NE: NaN ? notNaN : notEqual
       ├── OP_GE/GT/LE/LT: 对应比较表达式
       └── 左 Const 右 Column: 抛 FrontendException（非法排序）
```

## 5. 与其他模块的关系

| 关系模块 | 依赖方向 | 说明 |
|---|---|---|
| `iceberg-api` | 向下依赖 | `Schema`/`Table`/`Tables`/`TableScan`/`Expression` 抽象 |
| `iceberg-core` | 向下依赖 | `HadoopTables`/`CombinedScanTask`/`FileScanTask`/`PartitionSpec`/`SerializationUtil` |
| `iceberg-parquet` | 向下依赖 | `Parquet.read` 读构建器、`ParquetValueReader`/`ParquetValueReaders`/`TypeWithSchemaVisitor`/`ParquetSchemaUtil` |
| `iceberg-common` | 向下依赖 | relocated guava 工具类 |
| `iceberg-mr` | 无直接依赖 | Pig 模块独立于 mr 模块，不复用其 InputFormat；但 `iceberg-mr` 的 `InputFormatConfig.InMemoryDataModel.PIG` 枚举值表明 mr 模块曾计划支持 Pig（实际未实现，`IcebergInputFormat` 中 PIG 模式抛 `UnsupportedOperationException`） |

## 6. 设计亮点与权衡

### 6.1 frontend/backend 跨阶段配置传递

Pig 的执行分为 frontend（编译期，HiveServer2 侧）与 backend（executor 侧）两阶段，两阶段不共享 JVM。本模块通过 `UDFContext` + signature 隔离机制传递配置：frontend 把 schema/projection/filter 序列化进 `UDFContext`（按 signature 分组的 Properties），`setLocation` 阶段拷贝到 Hadoop Configuration（key 加 signature 后缀），backend InputFormat 按 signature 反查读取。这保证了同一 Job 内多个 `IcebergStorage` 实例的状态互不干扰。

### 6.2 双策略 Parquet 读取器

`PigParquetReader.buildReader` 检查文件 schema 是否含 field id：含 id 走 `ReadBuilder` 按 id 严格匹配（支持列重排/裁剪/分区注入/schema 演化），不含 id 走 `FallbackReadBuilder` 按位置回退匹配（兼容老文件）。这种双策略既享受了 Iceberg field id 带来的 schema 演化能力，又保证了对未写入 field id 的老 Parquet 文件的兼容。

### 6.3 分区列的虚拟注入

Iceberg 分区表的分区列值不写入数据文件，本模块在 struct 构造阶段通过 `ParquetValueReaders.constant` 把分区值作为常量读取器注入，并按 expected schema 顺序重排字段，保证输出 Tuple 列序符合 Pig 期望。读取时先从 `readSchema` 剔除分区列避免重复读，再用 `partitionValueMap` 按 fieldId 注入。

### 6.4 Pig bag 元素的 tuple 包装约束

Pig 的 `DataBag` 元素必须是 `Tuple`，但 Iceberg list 的元素可能是标量类型。`ArrayReader.addElement` 把每个元素包装为单字段 Tuple 后加入 DataBag，`SchemaUtil.convertComplex` 的 LIST 分支也对应地把非 struct 元素包一层 tuple schema。这是对 Pig 类型系统约束的必要妥协。

### 6.5 类型系统的"字符串化"妥协

Iceberg 的 DATE/TIMESTAMP 在 Pig 端被映射为 CHARARRAY（`DateReader` 输出 `yyyy-MM-dd`、`TimestampReader` 输出 ISO 字符串），而非 Pig 原生的 datetime 类型。这是因为 Pig 的 datetime 类型与 Iceberg 的时间语义（带/不带时区、微秒精度）难以直接对应，字符串化虽然损失了类型信息但保证了数据可读性与兼容性。

### 6.6 仅支持 Parquet 的局限性

本模块只支持 Parquet 文件格式（`advance` 方法中 `switch(file.format())` 仅处理 PARQUET 分支，其他抛 `UnsupportedOperationException`）。这是有意的权衡：Pig 生态以 Parquet 为主，且 `PigParquetReader` 直接依赖 `iceberg-parquet` 的 `TypeWithSchemaVisitor` 与 `ParquetValueReaders`，复用已有的列读取抽象。如需支持 ORC/Avro，需另行实现对应的 Pig 友好 reader。

### 6.7 谓词下推的 NaN 语义修正

`convert(op, col, constant)` 对 EQ/NE 特殊处理 NaN：若常量是 NaN，翻译为 `isNaN`/`notNaN` 而非 `equal`/`notEqual`，避免直接相等比较的语义问题（`NaN != NaN`）。这与 `iceberg-mr` 模块中 `HiveIcebergFilterFactory` 的 NaN 处理思路一致，体现了跨模块一致的语义修正。

### 6.8 可插拔 Tables 实现

通过 `pig.iceberg.tables.impl` 配置项可注入自定义 `Tables` 实现（默认 `HadoopTables`），使用 `ReflectionUtils.newInstance` 实例化。这让 Pig 模块能适配不同的表加载方式（如自定义 catalog），尽管默认仅支持基于路径的 `HadoopTables`，不直接对接 HiveCatalog/JDBC Catalog 等。

# Iceberg Parquet 模块架构与设计思路

> 源码路径：`parquet/src/main/java/org/apache/iceberg/parquet/`
> 模块工件：`iceberg-parquet`

## 1. 模块定位

`iceberg-parquet` 是 Iceberg 表格式与 Apache Parquet 列式文件格式之间的**桥接层与门面层**。在 Iceberg 整体架构中，它位于核心抽象层（`iceberg-core`）与计算引擎层（Spark / Flink / Trino 等）之间，承担以下职责：

- 把 Iceberg 的逻辑数据模型（`Schema`、`Type`、记录对象）与 Parquet 的物理存储模型（`MessageType`、列块、行组、页）相互转换。
- 提供统一的 Parquet 读写入口（`Parquet.write()` / `Parquet.read()`），屏蔽 parquet-mr 底层 API 的复杂性。
- 实现列投影、过滤下推（stats / dictionary / bloom filter 三重过滤）、metrics 收集、文件加密、NameMapping 兼容等 Iceberg 核心特性在 Parquet 格式上的落地。
- 同时支持逐行读取（`ParquetReader`）与向量化批量读取（`VectorizedParquetReader`），前者适配通用场景，后者适配列式执行引擎。

该模块是 Iceberg 默认且最成熟的数据文件格式实现，被 `iceberg-core` 的写入流程、`iceberg-arrow` 的向量化读取链路以及各引擎集成层共同依赖。

## 2. 包结构概览

本模块为单一包 `org.apache.iceberg.parquet`，按职责可划分为以下几组：

| 分组 | 核心类 | 职责 |
|------|--------|------|
| **门面与入口** | `Parquet` | 统一读写入口，提供 `WriteBuilder`/`ReadBuilder`/`DataWriteBuilder`/`DeleteWriteBuilder` 链式构造器 |
| **读取器** | `ParquetReader`、`VectorizedParquetReader`、`ReadConf`、`ParquetIterable` | 逐行/向量化文件读取器与读取配置中心 |
| **写入器** | `ParquetWriter`、`ParquetWriteAdapter` | 原生 Parquet 写入器与 parquet-mr 适配器（已废弃） |
| **值读取器** | `ParquetValueReader`、`ParquetValueReaders` | 读取侧核心抽象与各类型实现（struct/list/map/原始类型） |
| **值写入器** | `ParquetValueWriter`、`ParquetValueWriters` | 写入侧核心抽象与各类型实现 |
| **列迭代器** | `BaseColumnIterator`、`ColumnIterator`、`BasePageIterator`、`PageIterator`、`TripleIterator`、`ValuesAsBytesReader` | Parquet 列式读取底座，按页解码三元组（value+def level+rep level） |
| **Schema 转换** | `ParquetSchemaUtil`、`TypeToMessageType`、`MessageTypeToType`、`PruneColumns`、`ApplyNameMapping`、`RemoveIds` | Iceberg Schema 与 Parquet MessageType 的双向转换、列裁剪、ID 补全 |
| **Schema 遍历框架** | `ParquetTypeVisitor`、`TypeWithSchemaVisitor` | 访问者模式遍历 Parquet/Iceberg 类型树 |
| **过滤下推** | `ParquetMetricsRowGroupFilter`、`ParquetDictionaryRowGroupFilter`、`ParquetBloomRowGroupFilter`、`ParquetFilters` | 行组级统计/字典/布隆过滤与谓词转换 |
| **工具与 IO** | `ParquetUtil`、`ParquetIO`、`ParquetConversions`、`ParquetCodecFactory` | metrics 提取、文件 IO 适配、类型转换、压缩编解码工厂 |
| **Avro 兼容路径** | `ParquetAvro`、`ParquetAvroReader`、`ParquetAvroWriter`、`ParquetAvroValueReaders`、`ParquetReadSupport`、`ParquetWriteSupport` | 未提供原生 reader/writer 时的 Avro 回退路径 |
| **向量化抽象** | `VectorizedReader` | 向量化读取器接口（实现在 iceberg-arrow 模块） |

## 3. 核心类与设计模式

### 3.1 门面与 Builder 模式：`Parquet`

`Parquet` 是模块对外的唯一入口，采用**门面模式 + Builder 模式**：

- `WriteBuilder`：链式配置 schema、压缩、加密、metrics、行组/页大小等参数，`build()` 返回 `FileAppender`。
- `ReadBuilder`：链式配置投影 schema、过滤、split 范围、批大小、NameMapping 等，`build()` 返回 `CloseableIterable`。
- `DataWriteBuilder`：在 `WriteBuilder` 之上叠加分区 spec、partition、加密元数据、排序顺序，产出 `DataWriter`。
- `DeleteWriteBuilder`：可构建等值删除（`buildEqualityWriter`）或位置删除（`buildPositionWriter`）writer。

**双路径设计**：`build()` 时根据是否注入 `createWriterFunc` / `readerFunc` 选择路径：
- 注入时走 Iceberg 原生 `ParquetValueWriter` / `ParquetValueReader` 路径（推荐）。
- 未注入时回退到 parquet-mr 的 `WriteSupport` / `ReadSupport`（Avro）路径。

**Context 内部类**：将表属性解析与写入器构造解耦。`dataContext` 解析 `PARQUET_*` 属性，`deleteContext` 以 data 为默认值再用 `DELETE_PARQUET_*` 覆盖，删除文件不启用 bloom filter。

### 3.2 策略与组合模式：值读写器

`ParquetValueReader<T>` 与 `ParquetValueWriter<T>` 是读写侧的核心抽象接口：

- `read(T reuse)` / `write(int repetitionLevel, T value)`：按行读写。
- `columns()`：暴露持有的列三元组迭代器/写入器，供上层统一推进页源/列存储。
- `setPageSource()` / `setColumnStore()`：在新行组开始时下发页源/列存储。

`ParquetValueReaders` / `ParquetValueWriters` 以**组合模式**实现嵌套结构：
- `StructReader`/`StructWriter`：组合各字段子读写器，递归组装/拆解记录。
- `OptionReader`/`OptionWriter`：包装 OPTIONAL 列，通过 definition level 处理 null 语义。
- `ListReader`/`CollectionWriter`、`MapReader`/`MapWriter`：通过 repetition level 处理重复结构。
- `NullReader`/`ConstantReader`/`PositionReader`：处理缺失列、常量列、`_pos` 元数据列（空对象模式）。
- `IntAsLong`/`IntegerAsDecimal`/`BinaryAsDecimal` 等：类型提升与转换读取器。

### 3.3 迭代器模式：列式读取底座

读取底座分为三层，层层委托：

- `BaseColumnIterator`：按行组管理列读取状态（三元组总数、已读数、页边界），懒推进页（`advance()` 仅在到达边界时加载下一页）。
- `ColumnIterator`：实现 `TripleIterator` 接口，通过 `newIterator()` 工厂方法按原始类型创建强类型匿名子类，提供 `nextBoolean`/`nextInteger`/`nextLong` 等拆箱方法。
- `PageIterator`：负责单页数据的解码（含 def/rep level、字典解码）。
- `TripleIterator`：定义列值读取的统一抽象，`nextXxx()` 方法默认抛 `UnsupportedOperationException`，由具体实现按列类型重写。

### 3.4 访问者模式：Schema 转换与遍历

- `ParquetTypeVisitor<T>`：递归遍历 Parquet 类型树，维护字段名路径栈，提供 before/after 钩子。被 `MessageTypeToType`、`PruneColumns`、`ApplyNameMapping`、`RemoveIds` 继承。
- `TypeWithSchemaVisitor<T>`：**同时遍历 Iceberg Type 与 Parquet Type**，按字段 ID 对齐两棵树，处理 2-level/3-level LIST 编码与 Map key/value 投影。被各 reader/writer 构建器继承。
- `PruneColumns`：按字段 ID 集合裁剪 Parquet schema，被选中的 struct 祖先节点会被保留以确保嵌套结构完整。
- `ApplyNameMapping`：将 `NameMapping`（字段名路径→ID）物化到无 ID 的旧 Parquet schema 上，使其可按 ID 方式读取。
- `TypeToMessageType`：Iceberg→Parquet 转换，Decimal 按精度分级（≤9 用 INT32，≤18 用 INT64，否则 FIXED_LEN_BYTE_ARRAY），时间统一微秒。

### 3.5 配置中心：`ReadConf`

`ReadConf` 是读取侧的配置中心，集中封装：
- 打开 Parquet 文件、读取文件 schema、按 `expectedSchema` 做列投影（三路：hasIds / nameMapping / fallback）。
- 对每个行组应用 **stats + dictionary + bloom 三重过滤**，生成 `shouldSkip` 数组。
- 计算各行组起始行位置（用于 `_pos` 元数据列）与总值数。
- 按 `readerFunc` / `batchedReaderFunc` 构造逐行或向量化读取器。
- `copy()` 复制配置（reader 置 null，使用时重新打开文件），避免重复打开文件。

### 3.6 适配器模式：`ParquetWriteAdapter`

`ParquetWriteAdapter` 把 parquet-mr 的 `ParquetWriter` 适配为 Iceberg 的 `FileAppender` 接口，在 close 后从 footer 提取 metrics 与 split offsets。已标注 `@Deprecated`，生产环境应使用原生 `ParquetWriter`。

## 4. 关键流程

### 4.1 写入流程

```
Parquet.write(file)  /  Parquet.writeData(file)  /  Parquet.writeDeletes(file)
        │
        ▼
WriteBuilder / DataWriteBuilder / DeleteWriteBuilder  (链式配置)
        │  build()
        ▼
Context.dataContext / deleteContext  (解析表属性 → 行组/页/codec 参数)
        │
        ├── createWriterFunc != null ──▶ 原生 ParquetWriter
        │       │
        │       ▼  add(record)
        │   model.write(0, record)  →  ColumnWriteStore  →  ColumnChunkPageWriteStore
        │       │  checkSize() 自适应检查行组大小
        │       ▼  flushRowGroup()
        │   ParquetFileWriter.startBlock → flush → flushToFileWriter → endBlock
        │       │  close()
        │       ▼  writer.end(metadata)  →  footer + metrics
        │
        └── createWriterFunc == null ──▶ ParquetWriteAdapter (parquet-mr + AvroWriteSupport, 已废弃)
```

**写入要点**：
- 延迟初始化 writer：`ensureWriterInitialized()` 在首次 `flushRowGroup` 时才创建 `ParquetFileWriter`，避免空文件。
- 自适应行组检查：`checkSize()` 按平均记录大小动态调整下次检查点，平衡检查频率与性能。
- metrics 在 close 后才可获取，确保所有行组已 flush、footer 统计完整。

### 4.2 逐行读取流程

```
Parquet.read(file)  →  ReadBuilder  →  build()  →  ParquetReader (CloseableIterable)
        │  iterator()
        ▼
init()  →  ReadConf  (打开文件 / 投影 schema / 三重过滤行组 / 构造 ParquetValueReader)
        │
        ▼
FileIterator  (CloseableIterator<T>)
        │  hasNext() / next()
        ▼
advance()  ──  跳过 shouldSkip 行组  →  reader.readNextRowGroup()  →  model.setPageSource(pages, rowPos)
        │
        ▼
model.read(reuse)  →  ParquetValueReaders.StructReader  →  各字段子 reader
        │
        ▼
ColumnIterator.nextXxx()  →  PageIterator  (解码页内三元组)
```

**读取要点**：
- `alwaysTrue` 过滤表达式被替换为 null，避免无谓的谓词求值。
- 行组级跳过：`shouldSkip` 数组由三重过滤器预计算，`advance()` 跳过被过滤的行组。
- 容器复用：`reuseContainers` 时 `model.read(last)` 复用对象减少 GC。

### 4.3 向量化读取流程

向量化路径（`VectorizedParquetReader`）与逐行路径结构一致，区别在于：
- 使用 `batchedReaderFunc` 构造 `VectorizedReader`（而非 `ParquetValueReader`）。
- `FileIterator.next()` 每次读取 `min(行组剩余, batchSize)` 条记录，一次返回一个批次。
- `advance()` 通过 `model.setRowGroupInfo(pages, columnChunkMetadata, rowPosition)` 下发页源与列元数据。
- `VectorizedReader` 接口的实现在 `iceberg-arrow` 模块中（`VectorizedArrowReader`）。

### 4.4 过滤下推流程

`ReadConf` 构造时对每个行组依次应用三个过滤器（全部通过才读取）：

1. **`ParquetMetricsRowGroupFilter`**：基于列统计（min/max/null 计数），用 `BoundExpressionVisitor` 遍历表达式，对 eq/lt/gt/in/startsWith 等谓词判断行组是否可能包含匹配行。保守安全：统计缺失或含 null 时返回可能匹配。
2. **`ParquetDictionaryRowGroupFilter`**：基于字典值集合，判断谓词字面量是否在字典中。
3. **`ParquetBloomRowGroupFilter`**：基于布隆过滤器，判断值是否可能存在。

此外，Avro 回退路径还通过 `ParquetFilters` 将 Iceberg `Expression` 转换为 parquet-mr `FilterPredicate`，下推到 parquet-mr 层做行级过滤。

## 5. 与其他模块的关系

### 5.1 依赖的模块

- **iceberg-core**：`Schema`、`Type`/`Types`、`Expression`（过滤表达式）、`InputFile`/`OutputFile`/`FileAppender`（IO 抽象）、`Metrics`/`MetricsConfig`、`NameMapping`（字段名→ID 映射）、`TableProperties`（表属性常量）、`MetadataColumns`（元数据列）、`FieldMetrics`、`PartitionSpec`/`SortOrder`/`StructLike`、`DataWriter`/`EqualityDeleteWriter`/`PositionDeleteWriter`。
- **iceberg-avro**：`AvroSchemaUtil`（Avro schema 兼容处理），用于 Avro 回退路径与字段名规范化。
- **iceberg-hadoop**（运行时）：`HadoopInputFile`/`HadoopOutputFile`（Hadoop 文件系统适配）。
- **parquet-mr**：`ParquetFileReader`/`ParquetFileWriter`、`ColumnWriteStore`、`PageReadStore`、schema 类型、过滤 API（`FilterApi`/`FilterPredicate`）、加密属性。
- **Hadoop Common**：`Configuration`。

### 5.2 被依赖的模块

- **iceberg-arrow**：复用 `Parquet`（读写入口）、`VectorizedReader`（向量化接口）、`TypeWithSchemaVisitor`（schema 联合遍历）、`BaseColumnIterator`/`BasePageIterator`（列迭代器基类）、`ParquetUtil`、`ValuesAsBytesReader`。
- **iceberg-data**：`GenericParquetReader`/`GenericParquetWriter` 等通用数据模型读写器。
- **iceberg-spark / iceberg-flink / iceberg-trino**：各引擎集成层调用 `Parquet` 入口与值读写器构建器。
- **iceberg-core**（部分场景）：`DataFiles`、`GenericMcFileWriter` 等通过 `Parquet.writeData` 写数据文件。

## 6. 设计亮点与权衡

### 6.1 双路径设计兼顾灵活性与性能

读写入口均支持"原生路径"与"Avro 回退路径"双轨：
- 原生路径（`createWriterFunc`/`readerFunc`）由 Iceberg 完全掌控读写逻辑，支持字段 ID、metrics、类型提升等高级特性，性能更优。
- Avro 回退路径复用 parquet-mr 的 `WriteSupport`/`ReadSupport`，兼容旧集成方式与 Avro 记录模型。
- 权衡：维护两套路径增加了代码复杂度，但保证了向后兼容与渐进迁移。

### 6.2 字段 ID 为核心的 schema 演进

Iceberg 以字段 ID（而非字段名）追踪列，`ParquetSchemaUtil` 在 Iceberg Schema（ID 为核心）与 Parquet MessageType（名称为核心）间搭建桥梁：
- 写入时通过 `TypeToMessageType` 为每个字段保留 ID。
- 读取时通过 `hasIds` / `nameMapping` / `addFallbackIds` 三路处理，支持字段重命名/重排的 schema 演进，以及无 ID 的历史文件兼容。
- 权衡：ID 管理增加了一定复杂度，但从根本上解决了 schema 演进中的列匹配问题。

### 6.3 三重过滤最大化行组裁剪

`ReadConf` 对每个行组依次应用 stats / dictionary / bloom 三重过滤：
- stats 过滤开销最低（仅读元数据），先排除大部分不匹配行组。
- dictionary 与 bloom 过滤进一步精确裁剪。
- 权衡：多级过滤增加了构造期的 CPU 开销，但大幅减少数据 IO 与解码量，对大表扫描收益显著。

### 6.4 组合式值读写器适配复杂嵌套类型

通过 `StructReader`/`OptionReader`/`ListReader`/`MapReader` 等组合子读写器，递归处理任意深度的嵌套结构与 null 语义，由 definition/repetition level 驱动。
- 权衡：组合模式带来灵活性，但深嵌套结构的逐行读取仍有方法调用开销，因此引入向量化路径以适配列式引擎。

### 6.5 逐行与向量化双读取路径

- `ParquetReader`（逐行）适配通用场景与行式处理。
- `VectorizedParquetReader`（向量化）一次返回多行，减少虚函数调用与对象分配，适配 Spark 等列式引擎。向量化接口 `VectorizedReader` 定义在本模块，实现在 `iceberg-arrow`，实现关注点分离。
- 权衡：两套读取路径共享 `ReadConf` 与行组过滤逻辑，但迭代器实现各自独立，存在一定代码重复。

### 6.6 延迟初始化与自适应优化

- 写入器延迟初始化：首次 flush 时才创建 `ParquetFileWriter`，避免空文件。
- 自适应行组检查：按平均记录大小动态调整检查频率。
- 读取器延迟初始化：`ReadConf` 在首次 `iterator()` 时才构造并缓存，`copy()` 复用时 reader 置 null 按需重开。
- 权衡：延迟初始化增加了少量分支判断，但避免了无数据时的资源分配与空文件产生。

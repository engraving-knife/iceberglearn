# iceberg-aws 模块架构与设计思路

> 源码根目录：`aws/src/main/java/org/apache/iceberg/aws/`

## 1. 模块定位

`iceberg-aws` 是 Iceberg 与 AWS 托管服务集成的入口模块，处于 Iceberg `api/core` 之上、Spark/Flink 等计算引擎之下。它把 AWS S3、Glue、DynamoDB、KMS、Lake Formation、STS 等服务封装为 Iceberg 标准的 `Catalog`、`TableOperations`、`FileIO` 抽象，使 Iceberg 表能够在 AWS 原生数据湖栈上开箱即用。

模块对外承担两类职责：

- **元数据存储（Catalog）**：提供 `GlueCatalog`（基于 Glue Data Catalog）与 `DynamoDbCatalog`（基于 DynamoDB）两种实现，并配套 `DynamoDbLockManager` 提供分布式提交锁。
- **数据与元数据文件 IO（FileIO）**：通过 `S3FileIO` 把 S3 作为数据文件与元数据文件的底层存储，支持分片上传、批量删除、范围读取、SSE 加密、对象标签、远程签名等能力。

此外模块还提供 AWS 客户端工厂 SPI（`AwsClientFactory`）和 REST SigV4 签名能力，支撑跨账号（AssumeRole）、Lake Formation 凭证下发、REST Catalog 网关鉴权等企业级场景。

## 3. 核心类与设计模式

### 3.1 客户端工厂层（SPI + 工厂方法 + 反射加载）

| 类 | 设计意图 |
| --- | --- |
| `AwsClientFactory` | 客户端创建的 SPI 接口，定义 `s3()/glue()/kms()/dynamo()` 四个工厂方法与 `initialize(Map)`。实现 `Serializable` 以便在 Spark/Flink executor 上分发。 |
| `AwsClientFactories` | 静态工厂 + 反射加载器。通过 `client.factory` 配置项反射实例化自定义工厂，未配置时返回单例 `DefaultAwsClientFactory`。 |
| `DefaultAwsClientFactory` | 默认实现，使用 `applyMutation` 链式把 `AwsClientProperties`（区域）、`HttpClientProperties`（HTTP 客户端）、`S3FileIOProperties`（S3 端点/签名/凭证）、`AwsProperties`（Glue/DynamoDB 端点）叠加到 SDK builder。 |
| `AssumeRoleAwsClientFactory` | 跨账号场景实现。通过 STS `AssumeRole` 构造 `StsAssumeRoleCredentialsProvider`，由 SDK 自行刷新临时凭证；构造时生成 `iceberg-aws-<UUID>` 会话名便于 CloudTrail 审计。 |
| `LakeFormationAwsClientFactory` | 继承 `AssumeRoleAwsClientFactory`，对已注册到 Lake Formation 的表使用 `GetTemporaryGlueTableCredentials` 下发的临时凭证构造 S3/KMS 客户端，否则回退到 AssumeRole 凭证。 |
| `S3FileIOAwsClientFactories` | S3FileIO 专用加载器，优先加载 `S3FileIOAwsClientFactory`（仅构造 S3），未配置时回退到通用 `AwsClientFactory`，保证向后兼容。 |

**设计模式**：
- **策略模式**：`AwsClientFactory` 接口屏蔽不同凭证/端点策略，运行期通过反射选择具体实现。
- **建造者链式叠加**：借助 SDK 的 `applyMutation(Function)`，把多个 properties 对象的配置以无副作用方式叠加到 builder，避免巨型构造方法。
- **双轨加载**：`S3FileIOAwsClientFactories` 同时兼容专属工厂与通用工厂，平滑迁移。

### 3.2 配置持有者（参数对象 + 解析即校验）

| 类 | 职责 |
| --- | --- |
| `AwsProperties` | 集中定义并解析 Glue、DynamoDB、AssumeRole、REST SigV4 等场景的配置键与默认值，持有运行期可变状态（如 `glueCatalogId`、`glueLakeFormationEnabled`），并提供端点/凭证注入辅助方法。 |
| `AwsClientProperties` | 客户端区域、凭证提供者类名等通用配置，从 `AwsProperties` 拆分而来以避免膨胀。 |
| `HttpClientProperties` | HTTP 客户端类型（urlconnection/apache）及连接池、超时等配置。 |
| `S3FileIOProperties` | S3 FileIO 专属配置：SSE 加密、分片大小/阈值/线程数、staging 目录、Access Point 映射、标签、删除批大小、远程签名器等。 |

**设计模式**：
- **参数对象**：把零散 properties 收敛为强类型 holder，构造时一次性解析并缓存。
- **历史演进**：原 `AwsProperties` 承载过多职责，后续拆分出 `AwsClientProperties`/`HttpClientProperties`/`S3FileIOProperties`，旧方法保留 `@Deprecated` 以兼容。
- **可序列化**：所有 holder 实现 `Serializable`，支持分布式执行。

### 3.3 S3 FileIO（适配器 + 模板方法 + 惰性资源管理）

| 类 | 设计意图 |
| --- | --- |
| `S3FileIO` | 实现 `DelegateFileIO` 与 `CredentialSupplier`。无参构造器供反射加载，`initialize(Map)` 通过 `S3FileIOAwsClientFactories` 获取 S3 客户端 supplier。支持单文件删除、批量删除（按 bucket 分组、`deleteBatchSize` 触发批量 `DeleteObjects`）、`listPrefix`/`deletePrefix`、删除前打标签等。 |
| `BaseS3File` | `S3InputFile`/`S3OutputFile` 的抽象基类，封装 `S3Client`、`S3URI`、`S3FileIOProperties`、`MetricsContext`，惰性缓存 `HeadObject` 元数据。 |
| `S3InputFile`/`S3OutputFile` | 工厂方法创建对应的输入/输出流。 |
| `S3InputStream` | 实现 `SeekableInputStream` + `RangeReadable`。惰性打开流；**读穿缓存（read-through seek）**：向前 seek 较小距离时跳过已缓冲数据而非重新发请求；`readFully`/`readTail` 直接发带 range 的 GetObject；通过 `finalize` 兜底检测未关闭的流。 |
| `S3OutputStream` | 实现 `PositionOutputStream`。**本地暂存 + 分片上传**：数据先写本地临时文件，达到 `multiPartThresholdSize` 才初始化 Multipart Upload，分片通过 `CompletableFuture` 并发上传并立即删除暂存文件；小文件走 `PutObject`；支持 MD5 校验、标签、SSE、存储类别。 |
| `S3URI` | 自定义 URI 解析，避免 Hadoop Path 编码问题，支持 bucket→Access Point 映射。 |
| `S3RequestUtil` | 集中为 S3 请求注入 SSE 加密、ACL 权限等参数。 |

**设计模式**：
- **适配器模式**：把 S3 对象存储语义适配为 Iceberg 的 `InputFile`/`OutputFile`/`SeekableInputStream`/`PositionOutputStream`。
- **模板方法**：`BaseS3File` 提供公共骨架，子类实现具体流创建。
- **双重检查锁（DCL）**：`S3FileIO.client()`、`S3OutputStream.executorService` 用 volatile + DCL 延迟初始化共享资源。
- **资源兜底**：`finalize()` 检测未关闭的流/IO 并记录创建栈，缓解资源泄漏。
- **策略切换**：输出流根据写入量自动在 PutObject 与 Multipart Upload 间切换。

### 3.4 Glue Catalog（元数据存储 + 乐观锁 + 资源生命周期管理）

| 类 | 设计意图 |
| --- | --- |
| `GlueCatalog` | 继承 `BaseMetastoreCatalog`，实现 `SupportsNamespaces` 与 Hadoop `Configurable`。把 Glue Database/Table 映射为 Iceberg Namespace/TableIdentifier。支持 Lake Formation 启用校验、表级标签透传、warehouse 默认路径推导。 |
| `GlueTableOperations` | 继承 `BaseMetastoreTableOperations`。`doRefresh` 读取 Glue 表参数中的 `metadata_location`；`doCommit` 写新元数据文件→加锁→校验 base 与 Glue 一致→`persistGlueTable`（createTable/updateTable）→失败时通过 `RetryDetector` 与 `checkCommitStatus` 协调提交状态。 |
| `IcebergToGlueConverter` | Iceberg 标识符/Schema/属性 → Glue DatabaseInput/TableInput，做"尽力转换"供 Glue UI 展示（source of truth 仍在 Iceberg 元数据文件）。 |
| `GlueToIcebergConverter` | Glue Database/Table → Iceberg Namespace/TableIdentifier。 |

**设计模式**：
- **乐观锁优先**：通过 `DynMethods` 反射探测 SDK 是否支持 `UpdateTableRequest.versionId`，支持则用 Glue 表版本号做乐观锁，否则回退到外部 `LockManager`（推荐 DynamoDB）。`SET_VERSION_ID.isNoop()` 兼容老 SDK。
- **表级 FileIO 缓存**：`GlueCatalog` 用 Caffeine `weakKeys()` 缓存每个 `GlueTableOperations` 对应的 FileIO，当 TableOperations 被 GC 时自动关闭 FileIO，避免 Lake Formation 表级凭证场景下的资源泄漏。
- **异常映射**：`handleAWSExceptions` 把 Glue 的 `ConcurrentModificationException`/`AlreadyExistsException`/`EntityNotFoundException`/`AccessDeniedException` 等映射为 Iceberg 语义异常。
- **提交状态协调**：`RetryDetector` 作为 SDK `MetricPublisher` 注入 `UpdateTableRequest`，区分"未重试的失败"与"重试后可能成功"，再用 `checkCommitStatus` 校验元数据文件是否实际写入，避免 `CommitStateUnknownException` 误报。

### 3.5 DynamoDB Catalog（Serverless 元数据存储 + 乐观锁 + 原子事务）

| 类 | 设计意图 |
| --- | --- |
| `DynamoDbCatalog` | 用 DynamoDB 表作为元数据存储。复合主键 `identifier`(HASH) + `namespace`(RANGE)，GSI `namespace-identifier` 支持按命名空间列表。初始化时自动建表（PAY_PER_REQUEST）并轮询至 ACTIVE。 |
| `DynamoDbTableOperations` | 表级元数据 commit，通过 `version` 列（UUID）+ 条件表达式实现乐观锁。 |
| `DynamoDbLockManager` | 实现 `LockManagers.BaseLockManager`。租约 + 心跳模型：`acquireOnce` 用 `attribute_not_exists` 或版本匹配条件 PutItem 抢锁，持有者通过 `DynamoDbHeartbeat`（`scheduleAtFixedRate`）周期续约；过期后竞争者可基于版本号抢占，避免死锁。 |

**设计模式**：
- **条件表达式即并发控制**：所有写操作用 `conditionExpression` 把并发冲突交给 DynamoDB 服务端裁决。
- **原子 rename**：`renameTable` 用 `TransactWriteItems`（Delete + Put）保证原子性。
- **指数退避重试**：`Tasks.foreach().exponentialBackoff()` 对限流、事务冲突等可重试异常退避重试。
- **属性前缀隔离**：用户属性以 `p.` 前缀存储，与系统列（`identifier`/`version`/`created_at` 等）区分。

### 3.6 远程签名（REST SigV4）

| 类 | 设计意图 |
| --- | --- |
| `RESTSigV4Signer` | 实现 Apache HttpClient `HttpRequestInterceptor`，为 REST Catalog 请求计算 SigV4 签名（用于经 API Gateway/Lambda 代理的 REST Catalog）。复用 SDK `Aws4Signer`，对空 body 固定 `x-amz-content-sha256`，对冲突头改名为 `Original-` 前缀保留。 |
| `S3V4RestSignerClient` | 继承 SDK `AbstractAws4Signer`，把 S3 请求签名委托给远程 REST 服务。签名结果按 `method+region+uri` 缓存 30 秒（由服务端 `Cache-Control: private` 控制是否可缓存）；支持 OAuth2 client credentials flow 与令牌自动刷新。 |
| `S3SignRequest`/`S3SignResponse` 及 Parser | 远程签名协议的请求/响应模型与序列化器，使用 Immutables 生成不可变实现。 |

## 4. 关键流程

### 4.1 S3 文件读取流程（随机范围读取）

```
S3FileIO.newInputFile(path)
  └─ S3InputFile.fromLocation(path, client, props, metrics)
       └─ S3InputFile.newStream() → S3InputStream
            ├─ seek(pos): 仅记录 next=pos，不立即发请求（惰性）
            ├─ read()/read(b):
            │    └─ positionStream()
            │         ├─ next==pos: 已在位置，直接读
            │         ├─ next>pos 且距离小: skip 缓冲数据（读穿缓存）
            │         └─ 否则: closeStream() + openStream()
            │              └─ GetObject range=bytes=pos- （带 SSE 参数）
            ├─ readFully(pos, buf): 独立 GetObject range=bytes=pos-(pos+len-1)
            └─ readTail(buf): 独立 GetObject range=bytes=-len
```

要点：列式读取器（Parquet/ORC）频繁 seek，读穿缓存避免频繁重建 HTTP 流；范围读取不影响当前流位置。

### 4.2 S3 文件写入流程（暂存 + 分片上传）

```
S3FileIO.newOutputFile(path)
  └─ S3OutputFile.fromLocation → S3OutputStream
       ├─ 构造时: newStream() 创建首个本地暂存文件
       ├─ write(b):
       │    ├─ 当前暂存文件写满 multiPartSize → newStream() + uploadParts()
       │    └─ 总量达 multiPartThresholdSize → initializeMultiPartUpload()
       │         └─ CreateMultipartUpload（标签/存储类别/SSE/ACL）
       ├─ uploadParts(): 对已写满的暂存文件
       │    └─ CompletableFuture.supplyAsync(s3.uploadPart)
       │         └─ 完成后删除暂存文件
       ├─ close():
       │    ├─ 未进入分片模式: 串联暂存文件 → PutObject（含 MD5/标签/SSE）
       │    └─ 已进入分片模式: uploadParts() + completeMultiPartUpload()
       │         └─ 失败: abortUpload() + cleanUpStagingFiles()
       └─ finalize(): 兜底关闭未关闭的流
```

要点：S3 不支持追加，暂存文件解决"流式写对象"问题；延迟切换分片避免小文件走分片流程的开销；并发上传提升吞吐。

### 4.3 Glue 表提交流程（doCommit）

```
GlueTableOperations.doCommit(base, metadata)
  ├─ createGlueTempTableIfNecessary(): LakeFormation 新表场景先建临时表取 ARN
  ├─ writeNewMetadataIfRequired(): 写新元数据 JSON 到 S3
  ├─ lock(newMetadataLocation): LockManager.acquire 或乐观锁
  ├─ getGlueTable(): 读取当前 Glue 表
  ├─ checkMetadataLocation(): base 与 Glue 当前 location 必须一致
  ├─ prepareProperties(): 设置 TABLE_TYPE=ICEBERG, METADATA_LOCATION, PREVIOUS_METADATA_LOCATION
  ├─ persistGlueTable(retryDetector):
  │    ├─ 已有表: UpdateTableRequest
  │    │    └─ 若 SDK 支持 versionId 且无外部锁: SET_VERSION_ID(glueTable.versionId) 乐观锁
  │    └─ 新表: CreateTableRequest
  ├─ 异常处理:
  │    ├─ 非 AWS 异常 或 AWS 异常但发生重试: checkCommitStatus() 协调状态
  │    └─ AWS 异常: handleAWSExceptions() 映射为 Iceberg 异常
  └─ finally: cleanupMetadataAndUnlock()（失败删元数据文件+释放锁）
              cleanupGlueTempTableIfNecessary()（LakeFormation 临时表回滚）
```

### 4.4 DynamoDB 锁获取流程

```
DynamoDbLockManager.acquire(entityId, ownerId)
  └─ Tasks.exponentialBackoff(acquireInterval, acquireTimeout)
       └─ acquireOnce(entityId, ownerId)
            ├─ getItem(consistentRead=true)
            ├─ 无项: PutItem(condition=attribute_not_exists)  ← 直接抢
            ├─ 有项: sleep(leaseDuration) 等待过期
            │    └─ PutItem(condition=attribute_not_exists OR version=:vid)
            └─ startNewHeartbeat(entityId, ownerId)
                 └─ scheduler.scheduleAtFixedRate(heartbeat, intervalMs)
                      └─ PutItem(condition=entityId=:eid AND ownerId=:oid)  ← 续约
```

### 4.5 Lake Formation 凭证下发流程

```
GlueCatalog.newTableOps(identifier)
  └─ 若 glueLakeFormationEnabled:
       └─ 追加 LAKE_FORMATION_DB_NAME/TABLE_NAME 到表级 properties
       └─ PRELOAD_CLIENT_ENABLED=true（立即加载凭证）

GlueTableOperations.io() → initializeFileIO(tableProperties)
  └─ S3FileIO.initialize → S3FileIOAwsClientFactories.initialize
       └─ LakeFormationAwsClientFactory.s3()
            ├─ isTableRegisteredWithLakeFormation(): Glue GetTable 检查
            ├─ 已注册: S3Client.credentialsProvider(LakeFormationCredentialsProvider)
            │    └─ resolveCredentials(): GetTemporaryGlueTableCredentials
            │         └─ 返回 accessKeyId/secretAccessKey/sessionToken
            └─ 未注册: super.s3()（AssumeRole 凭证）
```

## 6. 设计亮点与权衡

### 6.1 可插拔的客户端工厂 SPI

通过 `AwsClientFactory` 接口 + `client.factory` 反射加载，把"如何构造 AWS 客户端"这一环境强相关决策推迟到运行期。默认实现覆盖大多数场景，`AssumeRoleAwsClientFactory`/`LakeFormationAwsClientFactory` 覆盖企业场景，用户也可自定义。代价是引入反射与无参构造器约束。

### 6.2 乐观锁优先 + 外部锁兜底

Glue 提交优先用 Glue 表版本号做乐观锁（无网络往返、无额外组件），仅在 SDK 不支持或用户显式配置时回退到 `DynamoDbLockManager`。通过 `DynMethods.orNoop()` 优雅兼容不同 SDK 版本。代价是老 SDK 用户需自行配置分布式锁。

### 6.3 提交状态协调避免未知态

`RetryDetector` 作为 `MetricPublisher` 注入 SDK 请求，精确区分"未重试失败"与"重试后失败"。结合 `checkCommitStatus` 二次校验元数据文件是否实际写入，最大程度减少 `CommitStateUnknownException`，提升流式提交的可靠性。

### 6.4 S3 写入的暂存 + 延迟分片策略

S3 不支持追加写入。`S3OutputStream` 用本地暂存文件缓冲，达到阈值才切换分片上传，避免小文件走分片流程的开销；分片并发上传并即时删除暂存文件，平衡吞吐与磁盘占用。代价是依赖本地磁盘空间，且暂存文件清理依赖 `finalize` 兜底。

### 6.5 读穿缓存优化随机读

`S3InputStream` 对小幅向前 seek 直接 skip 已缓冲数据，避免重建 HTTP 流，显著降低列式读取的 seek 开销。代价是流位置与 S3 请求位置可能不一致，需要 `pos`/`next` 双指针管理。

### 6.6 表级 FileIO 生命周期与 Lake Formation 凭证

`GlueCatalog` 用 Caffeine `weakKeys` 把 FileIO 与 TableOperations 绑定，GC 时自动关闭，解决 Lake Formation 表级临时凭证场景下 FileIO 频繁创建导致的资源泄漏。代价是 weak key 基于 identity 比较，需谨慎覆盖 equals/hashCode。

### 6.7 远程签名解耦凭证持有方

`S3V4RestSignerClient` 把签名计算委托给持有凭证的远程服务，客户端无需接触 AWS 凭证，适合通过中间签名服务代理 S3 访问的场景。签名结果缓存 30 秒降低远程调用频次。代价是不支持预签名与 payload 签名，且引入网络依赖。

### 6.8 配置持有者的演进式拆分

原 `AwsProperties` 承载所有 AWS 配置，随功能增长趋于臃肿。模块逐步拆分出 `AwsClientProperties`（区域/凭证）、`HttpClientProperties`（HTTP）、`S3FileIOProperties`（S3 专属），旧方法保留 `@Deprecated` 兼容。代价是短期内存在重复 API，需在 2.0.0 统一清理。

### 6.9 DynamoDB 作为 Serverless 元数据/锁存储

`DynamoDbCatalog` 与 `DynamoDbLockManager` 利用 DynamoDB 的强一致读、条件表达式、`TransactWriteItems` 实现元数据存储与分布式锁，无需维护数据库实例，适合云原生场景。代价是 DynamoDB 的查询模式受限（复合主键 + GSI），且属性前缀 `p.` 方案对复杂属性类型支持有限。

## 总体目的

这个提交属于 Iceberg 仓库的常规维护类改动（Infra），目的是在 GitHub Issue 模板里把最新发布版本号从 `1.4.1` 更新为刚发布的 `1.4.2`，从而让用户在提交 Bug 报告时能够选择正确的当前最新版本。

背景是：Iceberg 采用滚动发布策略，1.4.x 系列在 1.4.0、1.4.1 之后又发布了 1.4.2。Issue 模板中的版本下拉选项需要与实际发布保持同步，否则用户在报告问题时无法选到自己正在使用的最新版本，这会让维护者难以判断 Bug 是否已经在最新版本中修复。

具体改动是将 bug 报告模板 `.github/ISSUE_TEMPLATE/iceberg_bug_report.yml` 中版本下拉项的第一项 `"1.4.1 (latest release)"` 改为 `"1.4.2 (latest release)"`，并在其后保留一项 `"1.4.1"`，使得旧版本仍然可被选择以标记历史问题。这种"最新版本 + 历史版本并存"的写法是 Iceberg Issue 模板的一贯做法，便于对历史 Bug 进行归类。

这类改动虽然微小，但属于每次发版后必须跟进的仓库卫生工作，能确保用户反馈渠道与发布节奏一致。

## 如何达成设计目的

通过修改 GitHub Issue Bug 报告模板 YAML 文件中的 `options` 列表，把 `1.4.2` 提升为最新的可选项并标注 `(latest release)`，同时将原本的 `1.4.1` 降级为普通历史选项。改动只涉及一行被拆成两行，结构上没有引入新的表单字段或逻辑。

## 修改详情

### `.github/ISSUE_TEMPLATE/iceberg_bug_report.yml`

**修改目的**：把 Issue 模板中版本下拉的最新选项从 1.4.1 更新到 1.4.2，并保留 1.4.1 作为历史版本选项。

**工作逻辑**：在 `body` 下版本号 `options` 列表里，原来的首项 `- "1.4.1 (latest release)"` 被替换为两项：`- "1.4.2 (latest release)"` 和 `- "1.4.1"`。这样既更新了"最新版本"标记，又把上一版降级到普通历史版本列表里，保持与下方 `1.4.0`、`1.3.1`、`1.3.0` 等历史版本一致的格式。

## 小结

跟随 1.4.2 发版把 Issue 模板的最新版本选项同步更新，属于例行的仓库维护工作，确保用户反馈渠道与发布节奏一致。

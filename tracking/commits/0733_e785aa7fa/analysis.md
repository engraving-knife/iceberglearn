## 总体目的

本提交更新 Iceberg 仓库根目录下的 ASF 项目描述文件 `doap.rdf`，将其中记录的发布版本从 `1.5.0` 更新为 `1.5.1`，发布日期相应改为 `2024-04-25`。这是一项纯文档/元数据维护操作，目的是让 `doap.rdf` 反映最新的 Iceberg 发布版本，使 ASF 项目门户（projects.apache.org）抓取后能展示正确的当前版本信息。

**背景**：

1. **`doap.rdf` 是 ASF 描述项目的标准 RDF 文件**，其中 `<release>` 段记录项目的发布版本。ASF 项目聚合站点 `projects.apache.org` 会定期抓取各项目的 `doap.rdf`，展示项目最新版本及发布日期。若该文件未及时更新，外部用户通过 ASF 门户查询到的版本信息就会过期。

2. **本次更新对应 1.5.1 版本的发布**。Iceberg 1.5.1 于 2024-04-25 发布（按本提交填写的 `created` 日期），而此前 `doap.rdf` 中记录的还是 1.5.0（发布日期 2024-03-11）。本提交把这条记录替换为 1.5.1。

3. **本提交与 0731 号提交（`Release: add instruction to update doap.rdf file as part of release process`）形成呼应**：0731 把"更新 `doap.rdf`"写入发布流程文档，0733 则是对 1.5.1 发布按该流程执行的实际更新。二者在同一日（2024-04-30）合入，体现了"流程规范 + 实际执行"的闭环。

4. **注意**：本次更新是"替换"而非"追加"——`doap.rdf` 中只保留了一个 `<release>` 块（即最新版本 1.5.1），并未保留历史版本（1.5.0）的记录。这与 Iceberg 仓库 `doap.rdf` 的既有写法一致（改动前也只有一个 1.5.0 的块）。

## 如何达成设计目的

通过直接编辑 `doap.rdf` 文件中 `<release>` 段内的三个字段达成：
- `<name>`：`1.5.0` → `1.5.1`
- `<created>`：`2024-03-11` → `2024-04-25`
- `<revision>`：`1.5.0` → `1.5.1`

共 3 行修改（3 处替换，无新增/删除行），改动极小、目的明确。

**修改内容**（位于文件第 41-49 行附近的 `<release>` 块）：
```xml

<release>
  <Version>
    <name>1.5.0</name>
```

- `<revision>`：版本修订号，与 `<name>` 一致填版本号。

**未改动部分**：文件其余内容（项目名、描述、主页、邮件列表、SVN/Git 仓库地址、maintainer 等）均未改动。改动仅限 `<release>` 块内的三个字段值。

## 小结
- **成效**：成功将 `doap.rdf` 中的发布版本记录从 1.5.0 更新为 1.5.1（发布日期 2024-04-25），使 ASF 项目门户能展示 Iceberg 的最新发布版本。这是一次纯粹的元数据维护操作，与 0731 号提交引入的发布流程步骤相对应，是该流程首次被实际执行。
- **影响范围**：仅影响 `doap.rdf` 一个文件，不涉及任何代码或构建配置。影响对象是 ASF 项目门户（projects.apache.org）的展示内容和任何读取该 `doap.rdf` 的外部工具/脚本；对项目内部构建和运行时行为无影响。
- **回迁到 1.4.x 的注意事项**：通常**不需要回迁**本提交到 1.4.x 分支。原因：
  1. `doap.rdf` 记录的是项目整体的最新发布版本，而非某个分支的版本。1.5.1 是比 1.4.x 更新的版本，1.4.x 分支的 `doap.rdf` 应跟随项目主线版本走，不应回退到 1.4.x 自身的版本号；
  2. 若强行把 1.4.x 分支的 `doap.rdf` 改回 1.4.x 版本，反而会让 ASF 门户展示的版本回退，与实际项目发布状态不符；
  3. 因此本提交属于"main 分支独有、不应回迁"的类型。回迁评审时应在 1.4.x 的合并/挑选决策中标记为"无需回迁"。

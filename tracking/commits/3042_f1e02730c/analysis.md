## 总体目的

本提交为 GitHub Issue 模板中的 Bug 报告表单添加 1.10.1 版本选项，使其与刚刚发布的 1.10.1 维护版本同步。Apache Iceberg 使用 `.github/ISSUE_TEMPLATE/` 下的 YAML 表单模板（GitHub Issue Forms）来标准化用户提交 Bug 报告的格式，其中包含一个"使用的 Iceberg 版本"下拉选项字段，列出当前受支持的发布版本，便于维护者快速识别问题影响的版本范围。

1.10.1 发布后（见上一提交 3041 的站点更新），原模板的版本下拉仍以 `1.10.0 (latest release)` 为最新项，与实际最新发布版本不一致。这会导致用户在报告 1.10.1 相关问题时无法准确选择版本，要么选 1.10.0（语义错误），要么填"其他"（丢失结构化信息）。本提交将下拉项更新为以 1.10.1 为最新、1.10.0 降为普通历史版本项，使表单与发布状态保持一致。这是版本发布后流程闭环的一部分——除了站点文档（3041），Issue 模板也需同步反映新版本。

## 如何达成设计目的

改动仅涉及 Bug 报告表单 YAML 中版本下拉 `options` 数组的两行调整：新增 1.10.1 项并标注为 latest，同时把原 1.10.0 项的"(latest release)"标注去掉降级为历史版本。GitHub Issue Forms 会根据 `options` 列表渲染下拉选项，用户选择后该值作为结构化字段写入 Issue，便于后续按版本筛选与统计。

## 修改详情

### `.github/ISSUE_TEMPLATE/iceberg_bug_report.yml` (+2/-1 lines)

**修改目的**：在 Bug 报告表单的版本下拉中新增 1.10.1 并调整 1.10.0 的标注。

**工作逻辑**：
将版本字段的 `options` 数组首项由 `- "1.10.0 (latest release)"` 替换为两行：`- "1.10.1 (latest release)"` 与 `- "1.10.0"`。这样下拉列表顶部展示最新发布的 1.10.1，1.10.0 作为普通选项保留在其下（不再带 latest 标注）。其余历史版本（1.9.2、1.9.1、1.9.0 等）保持不变。修改后用户提交 Bug 时能准确选择 1.10.1，维护者也能按版本字段过滤 Issue。

## 总结

本提交是 1.10.1 发布后的 Issue 模板同步更新，在 Bug 报告表单的版本下拉中新增 1.10.1 为最新版本、将 1.10.0 降级为历史版本项。这是发布流程闭环的细节补全，确保用户提交问题时能准确标注所使用的 Iceberg 版本，便于维护者按版本分类与排查问题。

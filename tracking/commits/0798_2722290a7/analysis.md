## 总体目的

修复官网 CI 部署工作流的触发条件遗漏问题。Iceberg 官网采用多版本文档结构，1.4.0 及以后版本的文档存放在仓库根目录的 `docs/` 目录下（如 `docs/docs/1.4.0/`、`docs/docs/1.4.1/` 等 mkdocs 子站点）。然而官网部署工作流 `.github/workflows/site-ci.yml` 的 `paths` 触发过滤器原先只包含 `site/**`，未包含 `docs/**`。这导致当开发者仅修改 `docs/` 目录下的文档内容时，官网不会自动重新部署，造成线上文档与代码仓库不同步。

本提交的总体目的是：在 `site-ci.yml` 的 push 触发路径过滤器中新增 `docs/**`，使 `docs/` 目录下的文档变更也能触发官网自动部署。

## 如何达成设计目的

提交仅修改一处：在 `.github/workflows/site-ci.yml` 的 `on.push.paths` 列表中新增 `- docs/**`。

这样当 main 分支上有提交修改了 `docs/` 目录下任何文件时（包括各版本文档的 mkdocs.yml、Markdown 内容等），GitHub Actions 的 site-ci 工作流就会被触发，自动构建并部署更新后的官网。

## 修改详情

### `.github/workflows/site-ci.yml`

**修改目的**：扩展 site-ci 工作流的触发路径，使 `docs/` 目录的变更也能触发官网部署。

**工作逻辑**：该工作流文件定义了官网构建与部署的 CI 流程。其 `on.push` 配置限制了只在 main 分支且指定路径有变更时触发。修改前的 `paths` 列表仅含 `site/**`（即官网框架、主题、导航等配置文件所在的 `site/` 目录）。修改后在 `site/**` 之前新增一行 `docs/**`，使路径过滤器变为：

```yaml
paths:
  - docs/**
  - site/**
```

`docs/**` 通配 `docs/` 目录下所有层级的文件，覆盖 `docs/docs/<版本>/` 下的各版本文档子站点。这样无论是修改官网框架（`site/`）还是修改文档内容（`docs/`），都会触发部署。

## 小结

- **成效**：修复了文档变更不触发官网部署的遗漏，确保 `docs/` 目录下的任何文档修改（含各版本 mkdocs 子站点）推送到 main 分支后，官网能自动重建并发布，保持线上文档与仓库同步。
- **影响范围**：仅影响 GitHub Actions CI 工作流 `site-ci.yml` 的触发条件，不影响工作流内部的构建/部署步骤，也不涉及任何代码逻辑。
- **回迁注意事项**：本提交为 CI 配置变更，回迁到 1.4.x 分支无技术风险。需确认目标分支的 `site-ci.yml` 结构与 main 一致（即使用 `on.push.paths` 过滤器）。如果 1.4.x 分支的文档目录结构不同（如尚未采用 `docs/` 多版本结构），则该改动可能不适用或需调整路径模式。

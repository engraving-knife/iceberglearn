## 总体目的

这是一个非常小的仓库维护性提交，目的是把 GitHub issue 模板中 bug 报告表单的版本下拉选项更新到最新发布版本 1.4.3。Apache Iceberg 在 GitHub 上使用 issue 模板（`.github/ISSUE_TEMPLATE/iceberg_bug_report.yml`）来规范化用户提交 bug 报告的字段，其中"使用的 Iceberg 版本"是一个单选下拉框，列出当前受维护的版本供用户选择。每当 Iceberg 发布新版本（如 1.4.3），都需要把这个下拉框的选项同步更新：(a) 把新版本加到列表顶部并标注 "latest release"；(b) 把原标记为 "latest release" 的旧版本（1.4.2）去掉该标注，但仍保留在列表中供已部署旧版本的用户选择。

这种更新虽然微小但很重要——它直接影响 bug 报告的质量和分流效率。如果不更新，用户在提交 bug 时只能选到 1.4.2，维护者无法从 issue 标签上一眼看出用户是否已经用上最新版本，可能导致重复询问或误判为已修复问题。把最新版本放在第一位并标注 "latest release"，能引导用户优先确认是否在最新版本上复现，符合开源项目"先升级再报告"的最佳实践。

## 如何达成设计目的

实现路径极简：仅修改 `.github/ISSUE_TEMPLATE/iceberg_bug_report.yml` 一个文件，把版本下拉框的选项列表做一次"滚动更新"。原来列表第一项是 `"1.4.2 (latest release)"`，修改后变成两项：`"1.4.3 (latest release)"` 在前，`"1.4.2"` 在后（去掉 latest release 标注）。其余选项（1.4.1、1.4.0、1.3.1 等）保持不变。这种"加新项 + 改旧项标注"的模式每次发版都会重复一次，是 issue 模板维护的固定操作。

## 修改详情

### .github/ISSUE_TEMPLATE/iceberg_bug_report.yml

**修改目的**：把 bug 报告模板的版本下拉框更新到 Iceberg 1.4.3。

**工作逻辑**：该 YAML 文件定义 GitHub issue 表单结构。修改的部分是 `body` 下某个字段的 `attributes.options` 数组——即版本单选下拉框的可选项。原数组首项 `"1.4.2 (latest release)"` 被替换为两项：`"1.4.3 (latest release)"`（新增，置顶，标注为最新发布）和 `"1.4.2"`（保留旧版本但去掉 latest 标注）。这样用户打开 bug 报告表单时默认看到的首选项就是 1.4.3，引导用户确认是否在最新版本上复现；同时仍保留 1.4.2 选项供尚未升级的用户选择，避免用户因为找不到自己使用的版本而随意选一个不准确的版本。版本列表的顺序按从新到旧排列，符合用户预期。

## 小结

这是一个标准的版本同步维护提交，每次 Iceberg 发版后都会跟进一次。改动量极小（2 行新增、1 行删除），但体现了开源项目维护的两个良好实践：第一，issue 模板要随版本演进实时更新，确保收集到的版本信息准确、可用；第二，旧版本不立即从选项中删除，而是去掉 "latest release" 标注后保留，照顾还没升级的用户群。这种"加新留旧、滚动标注"的维护模式简单可靠，是 GitHub issue 模板管理的常见范式。这类提交虽然技术含量不高，却是项目运维健康度的一个细微信号——表明社区在持续发版、持续维护用户反馈通道。

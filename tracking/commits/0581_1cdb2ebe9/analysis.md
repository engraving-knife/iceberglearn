## 总体目的

Apache 软件基金会（ASF）要求每个顶级项目维护一份 DOAP（Description of a Project）文件 `doap.rdf`，用于在 https://projects.apache.org/ 上展示项目元数据，包括项目名称、简述、首页、邮件列表、版本控制系统以及已发布的版本（release）信息。该文件中 `<release>` 段落记录项目最新发布版本号和发布日期。

本提交的目的是将 Iceberg 项目 DOAP 文件中登记的"最新发布版本"从 1.4.3 更新为 1.5.0，使其与 1.5.0 版本正式发布（2024-03-11 投票通过）这一事实保持一致。这是项目发布流程中"对外公示发布信息"的一环，确保 ASF 项目目录、第三方索引平台以及下游使用者能够通过 DOAP 文件感知到 1.5.0 已经发布。

## 如何达成设计目的

实现方式非常直接：直接修改仓库根目录下的 `doap.rdf` 文件，将 `<release>/<Version>` 节点下的三个字段同步更新到 1.5.0 版本信息，无需任何代码逻辑改动或构建脚本调整。

具体来说：
- 把 `<name>` 由 `1.4.3` 改为 `1.5.0`；
- 把 `<created>`（发布创建日期）由 `2023-12-27` 改为 `2024-03-11`；
- 把 `<revision>`（版本修订号）由 `1.4.3` 改为 `1.5.0`。

由于 DOAP 文件采用 RDF/XML 格式，且 Iceberg 的 `doap.rdf` 只保留最新一个 release 条目（而非累积所有历史版本），所以这种"覆盖式"更新符合该文件的既有约定，由 Apache 项目目录系统在每次扫描时读取最新值。

## 修改详情

### `doap.rdf`

**修改目的**：将 DOAP 文件中登记的最新发布版本由 1.4.3 同步更新为 1.5.0，使 ASF 项目目录上的 Iceberg 信息与实际发布状态一致。

**工作逻辑**：仅替换 `<release>` 块中的三行内容，将版本名称、发布日期、版本修订号三项统一改为 1.5.0 相关信息。改动前后差异如下：

```diff
     <release>
       <Version>
-        <name>1.4.3</name>
-        <created>2023-12-27</created>
-        <revision>1.4.3</revision>
+        <name>1.5.0</name>
+        <created>2024-03-11</created>
+        <revision>1.5.0</revision>
       </Version>
     </release>
```

- `<name>`：发布版本的展示名称，从 `1.4.3` 升级到 `1.5.0`；
- `<created>`：发布日期，从 2023-12-27（1.4.3 发布日期）更新为 2024-03-11（1.5.0 发布日期）；
- `<revision>`：版本修订号，从 `1.4.3` 升级到 `1.5.0`，这是 DOAP 规范中用于唯一标识发布版本的字段。

## 小结

- **成效**：完成 1.5.0 版本发布后的 DOAP 元数据更新，使 ASF 项目目录页面能够正确展示 Iceberg 最新版本为 1.5.0。
- **影响范围**：仅影响仓库根目录的 `doap.rdf` 一个文件，3 行改动，无代码、构建、配置或文档逻辑变更，无功能影响。
- **回迁到 1.4.x 的注意事项**：该提交属于 main 分支 1.5.0 发布流程的一部分，**不应回迁到 1.4.x 分支**。1.4.x 维护分支的 DOAP 文件应当登记 1.4.x 系列最新版本（如 1.4.3 或后续的 1.4.x patch 版本），而非 1.5.0；如果将此提交 cherry-pick 到 1.4.x，会让 ASF 项目目录错误地显示 1.4.x 分支也发布了 1.5.0，造成版本信息混乱。1.4.x 分支应保留各自发布时对应的 DOAP 版本条目。

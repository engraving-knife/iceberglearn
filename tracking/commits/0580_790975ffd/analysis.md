## 总体目的

本提交更新 GitHub issue 模板，把 1.5.0 加入 Bug 报告表单的"Iceberg 版本"下拉选项，并顺带清理一批过旧的 0.x 版本选项。这是 1.5.0 发布（2024-03-11）配套的仓库基础设施维护，确保用户在提交 issue 时能选择正确的最新版本，同时避免下拉列表因积累过多历史版本而难以使用。属于纯仓库配置（`.github/`）改动，不涉及任何代码。

具体目标：
1. 将 1.5.0 标记为"最新发布版本"置于版本下拉首项；
2. 把原标记为最新的 1.4.3 降级为普通历史版本；
3. 移除 0.11.x ~ 0.14.x 共 8 个过于陈旧的版本选项，精简下拉列表。

## 如何达成设计目的

改动极简：仅修改 `.github/ISSUE_TEMPLATE/iceberg_bug_report.yml` 中 `version` 下拉字段的 `options` 列表——在顶部新增 `"1.5.0 (latest release)"`，把原 `"1.4.3 (latest release)"` 改为 `"1.4.3"`，并删除 8 个 0.x 旧版本条目。GitHub Issue 表单（YAML 格式）的下拉选项是纯静态文本，修改后用户下次提交 issue 时即可看到更新后的版本列表。`"main (development)"` 选项始终保留在末尾不变。

## 修改详情

### `.github/ISSUE_TEMPLATE/iceberg_bug_report.yml`

**修改目的**：更新 Bug 报告表单的版本下拉选项，反映 1.5.0 已成为最新发布版本。

**工作逻辑**：该文件是 GitHub Issue 表单（issue forms）配置，`version` 字段为 `dropdown` 类型，`options` 数组按顺序列出可选版本。改动分三部分：

1. **新增最新版本**：在 `options` 顶部新增 `- "1.5.0 (latest release)"`，作为默认首项。括号内的 `(latest release)` 是给用户的视觉提示，GitHub 表单会原样展示。
2. **降级原最新版本**：原 `- "1.4.3 (latest release)"` 改为 `- "1.4.3"`，去掉"最新发布"标记，归入历史版本。
3. **清理陈旧版本**：删除 8 个 0.x 版本条目：`0.14.1`、`0.14.0`、`0.13.1`、`0.13.0`、`0.12.1`、`0.12.0`、`0.11.1`、`0.11.0`。这些版本发布时间较早、使用率低，保留会拉长下拉列表；用户若确需针对这些版本提 issue，仍可在表单的描述区手动说明。

改动后版本列表为：`1.5.0 (latest release)` → `1.4.3` → `1.4.2` → `1.4.1` → `1.4.0` → `1.3.1` → `1.3.0` → `1.2.0` → `1.1.0` → `1.0.0` → `main (development)`，从最新到开发分支依次排列。`validations.required: false` 表示该字段非必填。

## 小结

本提交是 1.5.0 发布配套的仓库基础设施维护，通过更新 GitHub Bug 报告模板的版本下拉选项，把 1.5.0 设为最新发布版本、1.4.3 降级为历史版本，并清理 8 个过旧的 0.x 选项以精简列表。改动纯配置、无代码影响、无回滚风险。回迁到 1.4.x 时通常无需 cherry-pick（1.4.x 分支的 issue 模板应继续以 1.4.3 为最新版本）；若 1.4.x 也想引用 1.5.0 作为可选版本，可参考本提交的改法，但需保留 1.4.3 的"latest release"标记。

# iceberg-gcp 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-gcp` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-gcp` 是 Iceberg 的**云存储集成模块**之一，提供基于 **Google Cloud Storage (GCS)** 的 `FileIO` 实现（`GCSFileIO`）。它把 Iceberg 抽象文件接口适配到 GCS 对象存储语义，使 Iceberg 表可存储于 GCS。

## 2. 模块组成

| 类 | 职责 |
|---|---|
| `GCSFileIO` | 核心 `FileIO` 实现，管理 GCS 客户端与批量/前缀操作。 |
| `GCSLocation` | 解析 `gs://bucket/path` URI 为 bucket/prefix。 |
| `BaseGCSFile` | GCS 文件抽象基类，封装 location/client/properties/metrics。 |
| `GCSInputFile` / `GCSInputStream` | 输入文件与可寻址/范围读输入流（RangeReadable）。 |
| `GCSOutputFile` / `GCSOutputStream` | 输出文件与输出流。 |
| `GCPProperties` | GCP 配置集合（凭据/项目/超时/分块等）。 |

## 3. 整体架构

```
   core/引擎
      │ FileIO 抽象
      ▼
 ┌──────────────┐  ┌─────────────────┐
 │  GCSFileIO   │  │ GCPProperties    │ (凭据/项目/超时)
 └──┬───────────┘  └─────────────────┘
    │
 ┌──▼──────────────────────────┐
 │ GCSInputFile/OutputFile      │ ← BaseGCSFile ← GCSLocation
 │ + Input/OutputStream         │
 └────────────┬────────────────┘
              │
      ┌───────▼────────┐
      │  Google Cloud   │
      │  Storage SDK    │
      └────────────────┘
```

## 4. 核心设计思想

### 4.1 URI 解析与存储无关
`GCSLocation` 解析 `gs://` URI 为 bucket/prefix，使上层文件类与 GCS 细节解耦。

### 4.2 范围读与通道复用
`GCSInputStream` 实现 `RangeReadable`，按需打开读取通道并支持尾部读取（`readTail`）/完全读取（`readFully`），适配 GCS 的 HTTP Range 请求特性。

### 4.3 客户端生命周期与批量操作
`GCSFileIO` 集中管理 GCS 客户端创建/复用/关闭，提供批量删除、前缀列举/删除，对“不存在”容错以保证幂等清理。

### 4.4 配置与凭据分离
`GCPProperties` 集中管理 GCP 凭据、项目、超时等，便于在 FileIO 初始化时注入，支持多种 GCP 认证方式。

## 5. 上下游依赖关系

- **向上**：实现 `iceberg-api` 的 FileIO 接口，被 core 与引擎模块通过配置加载。
- **向下**：依赖 Google Cloud Storage 客户端库。
- **横向**：与 aws/azure/aliyun/dell 同属云存储集成层，互为平行实现。

## 6. 设计要点总结

1. **可插拔存储后端**：以标准 FileIO 接口适配 GCS。
2. **范围读 + 通道复用**：适配对象存储访问模式。
3. **批量幂等**：适合大规模表维护。
4. **配置解耦**：凭据/项目/超时集中管理。

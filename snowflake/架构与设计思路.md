# iceberg-snowflake 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-snowflake` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-snowflake` 是 Iceberg 的**目录服务集成模块**之一，提供基于 **Snowflake** 的 `Catalog` 实现（`SnowflakeCatalog`）。它通过 JDBC 查询 Snowflake 的内部表元数据，发现由 Snowflake 管理的 Iceberg 表（外部 Iceberg 表），使引擎能经由 Snowflake 目录加载这些表。

## 2. 模块组成

| 类 | 职责 |
|---|---|
| `SnowflakeCatalog` | 入口 `Catalog` 实现，listTables/loadNamespaceMetadata/newTableOps/initialize。 |
| `SnowflakeClient` / `JdbcSnowflakeClient` | 客户端接口与 JDBC 实现，CRUD + ResultSet 解析 + 异常映射。 |
| `SnowflakeTableOperations` | `TableOperations` 实现，`doRefresh` 加载表元数据位置。 |
| `SnowflakeTableMetadata` | 表元数据载体，含 JSON 解析工厂与路径语法转换。 |
| `SnowflakeIdentifier` | 标识符值对象（DB/Schema/Table 层级）。 |
| `NamespaceHelpers` | 命名空间与 Snowflake 标识符的互转工具。 |

## 3. 整体架构

```
   core/引擎
      │ Catalog 抽象
      ▼
 ┌──────────────────────┐
 │   SnowflakeCatalog    │  (list/load/initialize)
 └──────────┬───────────┘
            │
   ┌────────▼────────────┐
   │ JdbcSnowflakeClient  │  (JDBC 查询 + ResultSetParser + 异常映射)
   └────────┬────────────┘
            │
   ┌────────▼───────────────────┐
   │ SnowflakeTableOperations    │
   │ SnowflakeTableMetadata(解析)│
   └────────┬───────────────────┘
            │
   ┌────────▼────────┐
   │ Snowflake (JDBC) │
   └──────────────────┘
   旁路：NamespaceHelpers / SnowflakeIdentifier（命名空间↔标识符）
```

## 4. 核心设计思想

### 4.1 JDBC 元数据发现
Snowflake 把 Iceberg 表的元数据位置记录在其内部表中。`JdbcSnowflakeClient` 通过 JDBC 查询这些元数据，`ResultSetParser` 解析结果，把 Snowflake 的表视图映射为 Iceberg 表指针，复用 Snowflake 的发现能力而不依赖其事务。

### 4.2 标识符层级映射
`SnowflakeIdentifier` 表达 Snowflake 的 DB/Schema/Table 三级层级，`NamespaceHelpers` 在 Iceberg `Namespace` 与 Snowflake 标识符间互转，适配两者命名模型差异。

### 4.3 元数据 JSON 解析
`SnowflakeTableMetadata` 解析 Snowflake 返回的元数据 JSON，转换为 Iceberg metadata.json 位置，支撑 `SnowflakeTableOperations.doRefresh`。

### 4.4 异常映射
`JdbcSnowflakeClient` 把 JDBC 异常映射为 Iceberg 语义异常（表不存在/命名空间不存在等），统一错误模型。

### 4.5 能力边界
部分目录操作（dropTable/renameTable/createNamespace 等）当前抛 `UnsupportedOperationException`，反映 Snowflake 侧能力限制，已在 Javadoc 标注。

## 5. 上下游依赖关系

- **向上**：实现 `iceberg-api` 的 Catalog/TableOperations，被 core 与引擎使用。
- **向下**：依赖 Snowflake JDBC 驱动。
- **横向**：与 hive-metastore/nessie/jdbc/rest 同属目录层平行实现。

## 6. 设计要点总结

1. **JDBC 元数据发现**：复用 Snowflake 发现能力，不依赖其事务。
2. **标识符层级映射**：适配命名模型差异。
3. **JSON 元数据解析**：定位 Iceberg metadata.json。
4. **异常映射**：统一错误模型。
5. **能力边界明确**：不支持操作显式标注。

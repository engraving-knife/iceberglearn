# iceberg-dell 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-dell` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-dell` 是 Iceberg 的**云存储集成模块**之一，提供基于 **Dell ECS（Elastic Cloud Storage，S3 兼容）** 的 `FileIO` 与 `Catalog` 实现（`EcsFileIO`/`EcsCatalog`）。它把 Iceberg 抽象文件/目录接口适配到 Dell ECS，使 Iceberg 表可存储于 Dell ECS，并支持以 ECS 对象作为目录元数据载体。

## 2. 模块组成

**顶层**
- `DellProperties`：ECS 配置集合（endpoint/凭据/区域）。
- `DellClientFactory` / `DellClientFactories`：ECS 客户端工厂抽象与加载（支持自定义）。

**ecs 子包**
- `EcsFileIO`：核心 `FileIO` 实现，双重检查锁管理客户端、反射降级初始化指标、幂等关闭。
- `EcsCatalog`：`Catalog` 实现，namespace/table 全套操作，基于 ECS 对象的 CAS 读写。
- `EcsTableOperations`：`TableOperations` 实现，`doRefresh`/`doCommit` 使用 CAS 乐观锁。
- `EcsInputFile`/`EcsOutputFile`/`EcsSeekableInputStream`/`EcsAppendOutputStream`/`BaseEcsFile`：文件与流抽象。
- `EcsURI`：URI 解析。
- `PropertiesSerDesUtil`：版本化属性序列化。

## 3. 整体架构

```
   core/引擎
      │ FileIO / Catalog 抽象
      ▼
 ┌──────────────────────────────────┐
 │  EcsFileIO   /   EcsCatalog       │
 │  (客户端双重检查锁 / CAS 元数据)   │
 └──┬────────────────────────┬───────┘
    │ 文件 IO                 │ 目录元数据(CAS)
 ┌──▼──────────────┐   ┌──────▼───────────────┐
 │EcsInput/Output   │   │EcsTableOperations    │
 │File + Streams    │   │(doRefresh/doCommit)  │
 │← BaseEcsFile     │   │← PropertiesSerDesUtil│
 │← EcsURI          │   └──────────────────────┘
 └──────────────────┘
          │
   ┌──────▼────────┐
   │ Dell ECS (S3兼容)│
   └────────────────┘
```

## 4. 核心设计思想

### 4.1 CAS 乐观锁目录
EcsCatalog/EcsTableOperations 把目录元数据存为 ECS 对象，利用 ECS 的 `If-None-Match`（建对象）/`If-Match`（更新）实现 CAS 乐观并发控制，使无原生事务的 ECS 能支撑 Iceberg 的原子提交。

### 4.2 可插拔客户端工厂
`DellClientFactory` 抽象客户端创建，支持自定义凭据/endpoint 注入。

### 4.3 双重检查锁与反射降级
`EcsFileIO.client()` 用双重检查锁保证客户端单例安全初始化；`initMetrics` 通过反射加载指标类，缺失时降级，保证兼容性。

### 4.4 位置双值协调流
`EcsSeekableInputStream` 维护逻辑位置与底层流位置双值，`checkAndUseNewPos` 在定位偏离时重新打开，适配非完全可寻址的 ECS 流。

### 4.5 版本化序列化
`PropertiesSerDesUtil` 带版本号，支持目录属性格式演进。

## 5. 上下游依赖关系

- **向上**：实现 `iceberg-api` 的 FileIO/Catalog/TableOperations，被 core 与引擎使用。
- **向下**：依赖 Dell ECS S3 兼容 SDK。
- **横向**：与 aws/azure/gcp/aliyun 同属云存储集成层。

## 6. 设计要点总结

1. **CAS 乐观锁**：以对象存储条件请求支撑原子提交。
2. **可插拔客户端**：灵活接入凭据。
3. **双重检查锁 + 反射降级**：安全初始化与兼容性。
4. **位置双值流**：适配非完全可寻址流。
5. **版本化序列化**：元数据格式可演进。

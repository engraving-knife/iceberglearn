# iceberg-hive-metastore 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-hive-metastore` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-hive-metastore` 是 Iceberg 的**目录服务集成模块**之一，提供基于 **Hive Metastore (HMS) Thrift 客户端**的 `Catalog` 实现（`HiveCatalog`）。它把 Iceberg 表的元数据指针（指向 metadata.json 的位置）注册到 Hive Metastore 中，使 Hive 生态及通过 HMS 发现表的引擎能够识别并操作 Iceberg 表。

在分层中，它位于 `iceberg-api`/`iceberg-core` 之下，是“目录层”的可插拔实现之一（与 JDBC/REST/Nessie/Hadoop 等目录并列）。

## 2. 模块组成

| 类 | 职责 |
|---|---|
| `HiveCatalog` | 核心 `Catalog` 实现，对接 HMS 进行表的 CRUD/命名空间管理。 |
| `HiveClientPool` | HMS Thrift 客户端连接池，复用昂贵连接、支持重连。 |
| `CachedClientPool` | 带缓存的客户端池，按配置键缓存连接池实例。 |
| `HiveTableOperations` | `TableOperations` 实现，负责 Iceberg 表元数据在 HMS 上的 commit/refresh/persist。 |
| `HiveSchemaConverter` / `HiveSchemaUtil` | Iceberg Schema 与 Hive 类型之间的双向转换。 |
| `HiveLock` / `MetastoreLock` / `NoLock` | 提交并发控制：基于 HMS 锁的乐观/悲观锁抽象。 |
| `HiveVersion` / `HiveHadoopUtil` / `MetastoreUtil` | 版本探测、用户身份、alterTable 等辅助工具。 |
| `LockException` / `RuntimeMetaException` | 异常类型。 |

## 4. 核心设计思想

### 4.1 表指针注册模型
HiveCatalog 不把 Iceberg 完整元数据存入 HMS，而是在 HMS 表对象的 `location`/`TableParameters` 中保存指向 Iceberg `metadata.json` 的指针。HMS 仅作为“目录索引”，真正的表状态由 Iceberg 元数据文件管理。这是 Iceberg 与 HMS 集成的核心思想——**复用 HMS 的发现能力，但不依赖其事务语义**。

### 4.2 客户端连接池与缓存
HMS Thrift 客户端创建昂贵且非线程安全。`HiveClientPool` 维护客户端池复用连接；`CachedClientPool` 进一步按配置键缓存池实例，避免反复构建，兼顾性能与资源隔离。

### 4.3 提交并发控制
HMS 自身提供表级锁。`MetastoreLock` 利用 HMS 锁实现 Iceberg 提交的串行化，配合心跳保活；`HiveLock` 抽象出 lock/ensureActive/unlock 契约；`NoLock` 用于无需锁的场景。这把 Iceberg 的乐观提交模型与 HMS 锁机制对接，避免并发写冲突。

### 4.4 Schema 类型映射
`HiveSchemaConverter`/`HiveSchemaUtil` 处理 Iceberg 类型与 Hive 类型的不完全对齐（如 timestamp 精度、decimal、复杂类型），保证表在 Hive 侧可读。

### 4.5 版本探测与环境适配
`HiveVersion` 探测运行时 HMS 版本以选用兼容 API；`HiveHadoopUtil` 提供当前用户身份。屏蔽不同 Hive 版本差异。

## 5. 上下游依赖关系

- **向上**：实现 `iceberg-api` 的 `Catalog`/`TableOperations`，被 core 与 Hive/Spark/Flink 引擎使用。
- **向下**：依赖 Hive Metastore Thrift 客户端库与 Hadoop 配置。
- **横向**：与 `iceberg-core` 的 JDBC/REST/InMemory/Hadoop Catalog 同属目录层平行实现。

## 6. 设计要点总结

1. **指针式目录**：HMS 仅存表指针，元数据由 Iceberg 文件管理，解耦发现与状态。
2. **连接池 + 缓存**：应对 Thrift 客户端高昂创建成本。
3. **HMS 锁对接**：把 Iceberg 提交并发控制映射到 HMS 锁。
4. **类型映射**：处理 Iceberg↔Hive 类型差异。
5. **版本兼容**：运行时探测 HMS 版本，跨版本可用。

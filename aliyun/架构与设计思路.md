# iceberg-aliyun 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-aliyun` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-aliyun` 是 Iceberg 的**云存储集成模块**之一，提供基于**阿里云 OSS（对象存储服务）** 的 `FileIO` 实现（`OSSFileIO`）。它把 Iceberg 抽象文件接口适配到 OSS 对象存储语义，使 Iceberg 表可存储于阿里云 OSS。

## 2. 模块组成

| 类 | 职责 |
|---|---|
| `OSSFileIO` | 核心 `FileIO` 实现，管理 OSS 客户端与批量/前缀操作。 |
| `OSSURI` | 解析 `oss://bucket/path` URI 为 bucket/key。 |
| `BaseOSSFile` | OSS 文件抽象基类，封装 location/client/properties/metrics。 |
| `OSSInputFile` / `OSSInputStream` | 输入文件与可寻址/范围读输入流。 |
| `OSSOutputFile` / `OSSOutputStream` | 输出文件与缓冲分块上传输出流。 |
| `AliyunProperties` | OSS 配置集合（endpoint/凭据/分块大小/加密等）。 |
| `AliyunClientFactory` / `AliyunClientFactories` | OSS 客户端工厂抽象与实现（支持自定义凭据提供）。 |

## 3. 整体架构

```
   core/引擎
      │ FileIO 抽象
      ▼
 ┌──────────────┐   ┌─────────────────┐
 │  OSSFileIO   │   │ AliyunProperties │ (endpoint/凭据/分块)
 └──┬───────────┘   └─────────────────┘
    │
 ┌──▼──────────────────────┐
 │ OSSInputFile / OSSOutput│ ← BaseOSSFile ← OSSURI(URI 解析)
 │ File + Input/OutputStream│
 └────────────┬────────────┘
              │
      ┌───────▼────────┐
      │  AliyunClient   │ ← AliyunClientFactory(可自定义)
      │  Factory        │
      └───────┬────────┘
              │
      ┌───────▼────────┐
      │  阿里云 OSS SDK  │
      └────────────────┘
```

## 4. 核心设计思想

### 4.1 可插拔客户端工厂
`AliyunClientFactory` 抽象出 OSS 客户端创建，`AliyunClientFactories` 提供基于配置的默认实现并支持用户自定义工厂类，便于接入企业自有凭据体系（STS/RAM Role 等）。

### 4.2 URI 解析与存储无关
`OSSURI` 把 `oss://` URI 解析为 bucket/key，使上层文件类与 OSS 细节解耦。

### 4.3 范围读与缓冲写
- `OSSInputStream` 支持随机定位与范围读取，惰性定位减少多余请求。
- `OSSOutputStream` 缓冲并分块上传（Multipart Upload），`completeUploads` 完成合并，契合对象存储大文件上传特性。

### 4.4 批量与幂等操作
`OSSFileIO` 提供批量删除、前缀列举/删除，对“不存在”情形容错，保证幂等清理。

## 5. 上下游依赖关系

- **向上**：实现 `iceberg-api` 的 FileIO 接口，被 core 与引擎模块通过配置加载。
- **向下**：依赖阿里云 OSS SDK。
- **横向**：与 aws/azure/gcp/dell 同属云存储集成层，互为平行实现。

## 6. 设计要点总结

1. **可插拔客户端工厂**：灵活接入多种阿里云凭据方式。
2. **范围读 + 分块写**：适配对象存储访问模式。
3. **批量幂等**：适合大规模表维护。
4. **配置解耦**：endpoint/凭据/分块参数集中管理。

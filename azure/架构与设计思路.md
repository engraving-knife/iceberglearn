# iceberg-azure 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-azure` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-azure` 是 Iceberg 的**云存储集成模块**之一，为 Iceberg 提供基于 Azure Data Lake Storage (ADLS Gen2) 的 `FileIO` 实现。它把 Iceberg 的抽象文件接口（`InputFile`/`OutputFile`/`FileIO`）适配到 Azure Blob/ADLS 的对象存储语义上，使 Iceberg 表可以存储在 Azure 存储上。

在分层中，它位于 `iceberg-api`/`iceberg-core` 之下，作为可插拔的存储后端；引擎模块（spark/flink 等）通过 core 间接使用它。

## 2. 模块组成

本模块规模小（8 个类），围绕 ADLS 文件抽象与 FileIO 实现组织：

| 类 | 职责 |
|---|---|
| `ADLSLocation` | 解析 `abfs[s]://container@account/path` 形式 URI，拆分为 account/container/path。 |
| `BaseADLSFile` | ADLS 文件抽象基类，封装 location/client/properties/metrics 公共状态。 |
| `ADLSInputFile` | `InputFile` 实现，支持懒加载文件长度。 |
| `ADLSInputStream` | `SeekableInputStream`/`RangeReadable` 实现，支持随机定位与范围读取。 |
| `ADLSOutputFile` | `OutputFile` 实现，支持 create/createOrOverwrite 语义。 |
| `ADLSOutputStream` | `PositionOutputStream` 实现，缓冲写入并追踪位置。 |
| `AzureProperties` | Azure 配置集合，管理 SAS token / 连接字符串 / 块大小等。 |
| `ADLSFileIO` | 核心 `FileIO` 实现，管理客户端生命周期与批量删除/列举/前缀操作。 |

## 4. 核心设计思想

### 4.1 URI 解析与存储无关抽象
`ADLSLocation` 把 Azure 特有的 `abfs[s]://` URI 解析为统一的 account/container/path 三元组，使上层文件类无需关心 Azure URI 细节，符合 Iceberg “存储后端可插拔”的设计哲学。

### 4.2 懒加载与范围读取
- `ADLSInputFile` 懒加载文件长度（首读时才请求），减少不必要的远端调用。
- `ADLSInputStream` 实现 `RangeReadable`，定位时惰性记录目标位置，实际读取时按需发起来自该位置的范围请求，适配对象存储“按区间下载”特性，避免全量拉取。

### 4.3 缓冲写入
`ADLSOutputStream` 在客户端缓冲数据再分块上传，平衡网络往返开销与内存占用，契合云存储“少量大请求优于大量小请求”的性能特征。

### 4.4 客户端生命周期与批量操作
`ADLSFileIO` 集中管理 ADLS 客户端的生命周期（创建/复用/关闭），并提供批量删除（`deleteFiles`）、前缀列举/删除（`listPrefix`/`deletePrefix`）。设计上对 404 等“不存在”情形返回空而非抛错，保证幂等清理。

### 4.5 配置与凭据分离
`AzureProperties` 把 SAS token、连接字符串、块大小等配置与文件逻辑解耦，便于在 FileIO 初始化时统一注入，支持多种 Azure 认证方式。

## 5. 上下游依赖关系

- **向上**：实现 `iceberg-api` 的 `FileIO`/`InputFile`/`OutputFile`，被 `iceberg-core` 与各引擎模块通过配置加载使用。
- **向下**：依赖 Azure SDK（ADLS Gen2 客户端库）。
- **横向**：与 `iceberg-aws`/`iceberg-gcp`/`iceberg-aliyun`/`iceberg-dell` 同属云存储集成层，互为平行的可插拔实现。

## 6. 设计要点总结

1. **可插拔存储后端**：以标准 FileIO 接口适配 Azure，上层零感知。
2. **懒求值 + 范围读**：适配对象存储访问模式，降低延迟与流量。
3. **批量与幂等**：批量操作 + 容错 404，适合大规模表的维护清理。
4. **配置解耦**：凭据与连接参数集中管理，便于多认证方式切换。

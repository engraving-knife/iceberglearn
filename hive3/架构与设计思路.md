# iceberg-hive3 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-hive3` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-hive3` 是 Iceberg 与 **Hive 3** 引擎集成的**专属扩展模块**，提供 Hive 3 才有的能力：**向量化读取（Vectorized Read）**与 Hive 3 专属的 ObjectInspector 实现。它本身不独立工作，而是作为 `iceberg-mr` 的可选扩展，在运行期通过反射被加载。

在 Iceberg 整体分层中的位置：

```
        Hive 3 查询引擎（向量化执行）
                  │
        ┌─────────▼─────────┐
        │   iceberg-mr      │  ← 主体模块：StorageHandler/SerDe/InputFormat/OutputFormat
        │   (反射加载 hive3) │
        └─────────┬─────────┘
                  │ 反射加载（DynMethods/DynConstructors）
        ┌─────────▼─────────┐
        │   iceberg-hive3   │  ← 本模块：Hive 3 向量化 reader + Hive3 ObjectInspector
        │   (Hive 3 专属扩展)│
        └─────────┬─────────┘
                  │
   iceberg-core / iceberg-parquet / iceberg-orc / iceberg-hive3-orc-bundle
                  │
              iceberg-api
```

核心职责：

- 提供 Hive 3 向量化 RecordReader，把 Iceberg 数据以 `VectorizedRowBatch` 形式喂给 Hive 向量化执行引擎。
- 复用 Hive 自带的 `VectorizedParquetInputFormat`/`VectorizedOrcInputFormat`，并做 Iceberg 特有的适配（分区列注入、列名映射、ORC OrcTail 传递）。
- 提供 Hive 3 专属的 Date/Timestamp/TimestampWithZone ObjectInspector，处理 Hive 3 与 Hive 2 在这些类型上的 API 差异。
- 提供与 Hive 3 ORC shaded 库兼容的 `OrcSplit`（从 Hive 3 源码复制，解决 shaded ORC 兼容性问题）。

## 2. 包结构概览

本模块代码量小但分工明确，分布在两个包下：

## 3. 核心类与设计模式

### 3.1 向量化 RecordReader：`HiveIcebergVectorizedRecordReader`

继承 `AbstractMapredIcebergRecordReader<VectorizedRowBatch>`，是 MR v1 接口对 Iceberg v2 向量化 reader 的包装。

**职责**：

- `next`：调用内部 v2 reader 的 `nextKeyValue`，把产出的 `VectorizedRowBatch` 的 `cols`/`endOfFile`/`selectedInUse`/`size` 字段拷贝到 Hive 提供的 batch 对象。
- `createValue`：通过 `CompatibilityHiveVectorUtils.findMapWork(job).getVectorizedRowBatchCtx().createVectorizedRowBatch()` 创建符合 Hive 期望的 batch。
- `getPos`：返回 -1（向量化场景不追踪字节位置）。

**设计要点**：本类本身不读取数据，仅做 v1 → v2 接口桥接与 batch 字段拷贝。真正的读取逻辑在 `HiveVectorizedReader.reader` 中。

### 3.2 向量化 reader 工厂：`HiveVectorizedReader`

按文件格式创建匹配的 Hive 向量化 RecordReader，并对产出的 batch 做 Iceberg 特有适配。

**`reader` 方法核心逻辑**：

1. 从 `CompatibilityTaskAttemptContextImpl` 取出老版 `Reporter`（Hive 向量化 reader 需要）。
2. **分区列处理**：遍历 `PartitionSpec.fields`，对 identity 分区列：
   - 从 `readColumnIds` 中移除对应列（避免从数据文件重复读）。
   - 收集 `partitionColIndices` 与 `partitionValues`（来自 `idToConstant`）。
   - 重新设置 `ColumnProjectionUtils.setReadColumns`。
3. 按文件格式创建 Hive 原生向量化 reader：
   - **ORC**：`orcRecordReader` —— 构造 `OrcSplit`（携带 `OrcTail` 元数据），用 `VectorizedOrcInputFormat` 创建 reader。
   - **Parquet**：`parquetRecordReader` —— 读取 Parquet footer，按 field id 裁剪 schema，用 `ParquetSchemaFieldNameVisitor` 收集列名写入 `IOConstants.COLUMNS`，用 `VectorizedParquetInputFormat` 创建 reader。
4. 用 `createVectorizedRowBatchIterable` 包装为 `CloseableIterable`。

**设计模式**：工厂方法 + 策略模式。按 `FileFormat` 选择不同的 reader 创建策略，统一返回 `CloseableIterable`。

### 3.3 batch 迭代器：`VectorizedRowBatchIterator`

实现 `CloseableIterator<VectorizedRowBatch>`，包装 Hive 的 `RecordReader`。

**`advance` 方法**：

1. 调用 `recordReader.next(key, batch)` 读取下一批。
2. **填充分区列**：若 `partitionColIndices` 非空，对每个分区列索引调用 `CompatibilityHiveVectorUtils.addPartitionColsToBatch`，把分区常量值填充到 batch 的对应 `ColumnVector`。
3. `advanced` 标志位防止重复 advance。

**设计要点**：分区列不在数据文件中，Hive 向量化 reader 不会自动填充，必须由本迭代器在每批数据后手动注入。这是 Iceberg 分区模型与 Hive 向量化读取的关键衔接点。

### 3.4 兼容工具：`CompatibilityHiveVectorUtils`

包含从 Hive 后续版本源码移植的方法，注释明确说明"应在 Hive 4 发布后删除本类"。

**`findMapWork`**：从 JobConf 中查找序列化的 `MapWork` 实例（移植自 `LlapHiveUtils#findMapWork`），处理 Tez SMB join 的特殊路径。

**`addPartitionColsToBatch`**：把分区值填充到 `ColumnVector`（移植自 `VectorizedRowBatchCtx#addPartitionColsToBatch`）。按 `PrimitiveCategory` 分支处理：

- BOOLEAN/BYTE/SHORT/INT/LONG/DATE/INTERVAL_YEAR_MONTH → `LongColumnVector.fill`。
- FLOAT/DOUBLE → `DoubleColumnVector.fill`。
- TIMESTAMP → `TimestampColumnVector.fill`。
- INTERVAL_DAY_TIME → `IntervalDayTimeColumnVector.fill`。
- DECIMAL → `DecimalColumnVector.set` + `isRepeating`。
- BINARY → `BytesColumnVector.fill`。
- STRING/CHAR/VARCHAR → `BytesColumnVector.setVal` + `isRepeating`。
- null 值 → 设置 `noNulls=false`/`isNull[0]=true`/`isRepeating=true`。

### 3.5 Parquet 列名收集：`ParquetSchemaFieldNameVisitor`

继承 `TypeWithSchemaVisitor<Type>`，收集顶层字段名列表，写入 `IOConstants.COLUMNS` 供 Hive Parquet reader 使用。

**核心问题**：Iceberg 支持列重命名（通过 field id 跟踪），但 Hive Parquet reader 按列名匹配。本访问器在 schema 遍历过程中：

- 对每个 expected 字段，按 field id 在文件 schema 中查找：
  - 命中：使用文件中的原始列名（即使 expected 已重命名）。
  - 未命中且文件中无此列名：新字段，使用 expected 列名（Hive reader 会返回 null）。
  - 未命中但文件中有此列名（不同 id）：字段被重建，插入 `DUMMY_COL_NAME` 强制 Hive reader 返回 null。
- 跳过 `MetadataColumns`（元数据字段）。

**设计意图**：把 Iceberg 的 field id 语义翻译为 Hive Parquet reader 能理解的列名语义，正确处理列重命名、列新增、列重建三种 schema 演化场景。

### 3.6 ORC 向量化辅助：`VectorizedReadUtils`

提供 `getOrcTail` 方法：打开 ORC 文件读取元数据，构造 `OrcTail`。

**设计原因**：Hive 向量化 ORC reader 需要在 `OrcSplit` 中传入 `OrcTail` 元数据，否则会假设 ORC 文件在 `task.start + task.length` 处结束而读取失败。本方法通过 `ReaderImpl.extractFileTail` 从序列化的 footer 中提取 `OrcTail`。

### 3.7 Hive3 ObjectInspector 系列

三个类（`IcebergDateObjectInspectorHive3`/`IcebergTimestampObjectInspectorHive3`/`IcebergTimestampWithZoneObjectInspectorHive3`）提供 Hive 3 专属的 Date/Timestamp/TimestampTZ ObjectInspector 实现。

**共同特征**：

- 单例模式（`INSTANCE` + `get()`）。
- 同时实现 Hive OI 接口与 `WriteObjectInspector`，兼顾读呈现与写转换。
- `convert` 方法把 Hive 3 类型对象转为 Iceberg 期望的 `java.time` 类型。
- `getPrimitiveJavaObject` 把 Iceberg `java.time` 类型转为 Hive 3 类型对象。

**类型映射**：

| 类 | Hive 3 类型 | Iceberg 类型 |
|---|---|---|
| `IcebergDateObjectInspectorHive3` | `org.apache.hadoop.hive.common.type.Date` | `java.time.LocalDate` |
| `IcebergTimestampObjectInspectorHive3` | `org.apache.hadoop.hive.common.type.Timestamp` | `java.time.LocalDateTime` |
| `IcebergTimestampWithZoneObjectInspectorHive3` | `org.apache.hadoop.hive.common.type.TimestampTZ` | `java.time.OffsetDateTime` |

**为什么需要 Hive3 专属版本**：Hive 2 与 Hive 3 在 Date/Timestamp ObjectInspector 上有破坏性 API 变更（`DateObjectInspector`/`TimestampObjectInspector` 接口方法签名不同，Hive 3 引入了 `TimestampLocalTZObjectInspector`）。`iceberg-mr` 模块中的 `IcebergObjectInspector` 通过 `DynMethods` 反射按 `HiveVersion` 加载对应版本的实现类。

### 3.8 复制的 OrcSplit：`org.apache.hadoop.hive.ql.io.orc.OrcSplit`

从 Hive 3.x 源码完整复制的 `OrcSplit` 类，位于 `org.apache.hadoop.hive.ql.io.orc` 包下（与 Hive 原包名一致）。

**设计原因**（类注释明确说明）：解决 Hive 3.x 与 shaded ORC 库的兼容性问题。Hive 3 的 `OrcSplit` 依赖特定版本的 ORC 类，而 Iceberg 使用 shaded ORC（`hive3-orc-bundle`），导致 Hive 原生 `OrcSplit` 无法直接使用。复制一份到本模块后，可针对 shaded ORC 重新编译。注释提到"应在 Hive 4 发布后删除本类"。

## 4. 关键流程

### 4.1 Hive 3 向量化读取

```
Hive 3 查询（向量化执行开启）
   │
   ▼
HiveIcebergInputFormat.getRecordReader (iceberg-mr 模块)
   │  - 检测 HIVE_VECTORIZATION_ENABLED && VectorizedRowBatchCtx != null
   │  - HiveVersion.min(HIVE_3) 校验
   │  - 设置 IN_MEMORY_DATA_MODEL=HIVE, SKIP_RESIDUAL_FILTERING=true
   │  - 反射构造 HiveIcebergVectorizedRecordReader（本模块）
   ▼
HiveIcebergVectorizedRecordReader (extends AbstractMapredIcebergRecordReader)
   │  - 构造时调用 super -> 内部 v2 reader = IcebergInputFormat.createRecordReader
   │  - initialize -> IcebergRecordReader.initialize
   │     - 按 HIVE 模式打开文件
   │     - openTask -> newParquetIterable/newOrcIterable
   │       - HIVE 模式反射调用 HiveVectorizedReader.reader（本模块）
   ▼
HiveVectorizedReader.reader
   │  1. 取出老版 Reporter
   │  2. 分区列处理：移除 identity 分区列的 readColumnIds，收集 partitionColIndices/Values
   │  3. 按格式创建 Hive 原生向量化 reader：
   │     - ORC: VectorizedReadUtils.getOrcTail -> OrcSplit -> VectorizedOrcInputFormat
   │     - Parquet: 读 footer -> ParquetSchemaFieldNameVisitor 收集列名 -> VectorizedParquetInputFormat
   │  4. createVectorizedRowBatchIterable 包装
   ▼
VectorizedRowBatchIterator.advance
   │  - recordReader.next(key, batch)
   │  - CompatibilityHiveVectorUtils.addPartitionColsToBatch 填充分区列常量
   ▼
HiveIcebergVectorizedRecordReader.next
   │  - innerReader.nextKeyValue
   │  - 拷贝 batch 字段到 Hive 提供的 batch
   ▼
Hive 向量化执行引擎消费 VectorizedRowBatch
```

### 4.2 Hive3 ObjectInspector 加载

```
IcebergObjectInspector 静态初始化 (iceberg-mr 模块)
   │
   ▼ 按 HiveVersion 选择类名
   ├── Hive 3+: "org.apache.iceberg.mr.hive.serde.objectinspector.IcebergDateObjectInspectorHive3"
   │            "org.apache.iceberg.mr.hive.serde.objectinspector.IcebergTimestampObjectInspectorHive3"
   │            "org.apache.iceberg.mr.hive.serde.objectinspector.IcebergTimestampWithZoneObjectInspectorHive3"
   └── Hive 2:  "org.apache.iceberg.mr.hive.serde.objectinspector.IcebergDateObjectInspector"
                ...
   │
   ▼ DynMethods.builder("get").impl(className).buildStatic().invoke()
   │
   ▼ 返回单例 ObjectInspector（DATE_INSPECTOR/TIMESTAMP_INSPECTOR/TIMESTAMP_INSPECTOR_WITH_TZ）
```

## 6. 设计亮点与权衡

### 6.1 反射解耦的跨版本兼容架构

本模块存在的根本原因是为 `iceberg-mr` 提供 Hive 3 专属能力的"可选扩展"。`iceberg-mr` 通过 `DynMethods`/`DynConstructors` 反射加载本模块的类（`HiveVectorizedReader`/`HiveIcebergVectorizedRecordReader`/`*Hive3` ObjectInspector），编译期不依赖本模块，运行期按 `HiveVersion.min(HIVE_3)` 决定是否激活。这是 Iceberg 跨 Hive 版本兼容的核心架构决策：

- `iceberg-mr` 编译期只依赖 Hive 2 类，保证能在 Hive 2 运行。
- `iceberg-hive3` 编译期依赖 Hive 3 类，提供 Hive 3 专属能力。
- 部署时按目标 Hive 版本选择是否引入 `iceberg-hive3` 依赖。

### 6.2 复用 Hive 原生向量化 reader

本模块没有重新实现 Parquet/ORC 的向量化读取，而是直接复用 Hive 自带的 `VectorizedParquetInputFormat`/`VectorizedOrcInputFormat`。这避免了重复造轮子，能持续享受 Hive 向量化 reader 的优化。代价是需要做 Iceberg 特有的适配：

- **分区列注入**：Hive 向量化 reader 不会自动填充 Iceberg 分区列，需在 `VectorizedRowBatchIterator` 中手动调用 `addPartitionColsToBatch`。
- **列名映射**：Iceberg 用 field id 跟踪列，Hive 按列名匹配，需 `ParquetSchemaFieldNameVisitor` 翻译。
- **ORC OrcTail 传递**：Hive 向量化 ORC reader 需要在 split 中传入 `OrcTail`，否则读取失败。

### 6.3 分区列的"移除-注入"两步处理

向量化读取分区表时，本模块采用两步策略：

1. **移除**：从 `ColumnProjectionUtils.getReadColumnIDs` 中移除 identity 分区列，避免 Hive reader 从数据文件中重复读取（数据文件中本就没有分区列，读取会出错）。
2. **注入**：在每批数据后通过 `addPartitionColsToBatch` 把分区常量值填充到 batch 的对应 `ColumnVector`，设置 `isRepeating=true`。

这种处理让 Hive 向量化 reader 专注于数据列读取，分区列由 Iceberg 侧统一注入，保证了向量化执行的正确性与性能。

### 6.4 Schema 演化的列名翻译

`ParquetSchemaFieldNameVisitor` 处理三种 schema 演化场景：

- **列重命名**：expected 用新名，文件用旧名，按 field id 匹配后使用文件旧名（Hive reader 按名读取）。
- **列新增**：expected 有而文件无，使用 expected 新名（Hive reader 返回 null）。
- **列重建**：expected 与文件同名但 field id 不同（说明字段被删除后重建），插入 `DUMMY_COL_NAME` 强制 Hive reader 返回 null，避免读到旧数据。

这种基于 field id 的列名翻译是 Iceberg schema 演化能力在 Hive 向量化场景下的具体落地。

### 6.5 临时性兼容代码的明确边界

`CompatibilityHiveVectorUtils` 与复制的 `OrcSplit` 都带有明确的"临时"注释：

- `CompatibilityHiveVectorUtils`：注释说明"包含从 Hive 后续源码移植的代码片段，Hive 4 发布后应删除本类"。
- `OrcSplit`：注释说明"为解决 Hive 3.x 与 shaded ORC 库的兼容性问题从 Hive 3.x 源码复制，Hive 4 发布后应删除"。

这种明确的临时性标记让未来升级 Hive 4 时的清理工作有据可依，体现了对技术债务的自觉管理。

### 6.6 测试源码复用

`build.gradle` 中 `sourceSets.test.java.srcDirs = ['../mr/src/test/java', 'src/test/java']`，本模块直接复用 `iceberg-mr` 的测试源码目录，仅排除 Hive 2 专属的 ObjectInspector 测试（`TestIcebergDateObjectInspector`/`TestIcebergTimestampObjectInspector`/`TestIcebergTimestampWithZoneObjectInspector`）。这避免了测试代码重复，同一套测试在 Hive 3 依赖下验证 mr 模块的功能正确性。

### 6.7 ObjectInspector 的读写双重职责

三个 Hive3 ObjectInspector 都同时实现 Hive OI 接口与 `WriteObjectInspector`：

- **读呈现**（`getPrimitiveJavaObject`）：把 Iceberg `java.time` 类型转为 Hive 3 类型对象。
- **写转换**（`convert`）：把 Hive 3 类型对象转为 Iceberg `java.time` 类型。

这让同一套 OI 既能服务于 Hive 读取（呈现 Iceberg Record 给 Hive），也能服务于 Hive 写入（把 Hive 行转为 Iceberg Record），与 `iceberg-mr` 中其他 ObjectInspector 的设计保持一致。

### 6.8 仅支持 Parquet 与 ORC 的向量化

`HiveVectorizedReader.reader` 的 `switch(format)` 仅处理 `ORC` 与 `PARQUET`，其他格式抛 `UnsupportedOperationException`。这与 Hive 自身向量化 reader 的支持范围一致（Hive 仅对 Parquet/ORC 提供向量化 reader）。Avro 等格式的向量化读取在 Hive 生态中本身就不常见，本模块未实现是合理的权衡。

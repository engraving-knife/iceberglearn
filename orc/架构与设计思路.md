# iceberg-orc 模块架构与设计思路

> 本文档由源码注释整理生成，描述 `iceberg-orc` 模块的设计架构与设计思路。

## 1. 模块定位

`iceberg-orc` 是 Iceberg 的**列式格式集成模块**之一，为 Iceberg 提供 **ORC 文件格式**的读写与指标支持。它把 Iceberg 的类型系统、Schema、表达式与 ORC 的类型/Reader/Writer/谓词下推对接，使 Iceberg 表可以使用 ORC 作为数据文件格式。

## 2. 模块组成（按职责分组）

**入口与构建器（`ORC.java`）**：统一的 WriteBuilder/DataWriteBuilder/DeleteWriteBuilder/ReadBuilder 与 Context，是 ORC 读写的主入口。

**Schema 映射**
- `ORCSchemaUtil` / `OrcSchemaVisitor` / `OrcSchemaWithTypeVisitor` / `OrcToIcebergVisitor`：Iceberg Schema ↔ ORC Type 双向转换。
- `IdToOrcName` / `HasIds` / `RemoveIds` / `ApplyNameMapping`：字段 ID 在 ORC 中的表示与 NameMapping 兼容（ORC 无原生字段 ID，靠命名约定承载）。

**读取**
- `OrcValueReader` / `OrcValueReaders` / `OrcRowReader` / `OrcBatchReader` / `VectorizedRowBatchIterator`：ORC 向量批 → Iceberg 值的读取器族，支持向量化。
- `GenericOrcReader` / `GenericOrcReaders`：通用记录读取。

**写入**
- `OrcValueWriter` / `OrcRowWriter` / `GenericOrcWriter` / `GenericOrcWriters`：Iceberg 值 → ORC 向量的写入器族。
- `OrcFileAppender`：文件追加写封装。

**指标与谓词下推**
- `OrcMetrics`：从 ORC 文件收集统计指标。
- `ExpressionToSearchArgument`：把 Iceberg 表达式转为 ORC `SearchArgument` 实现谓词下推。

**辅助**：`FileIOFSUtil`、`EstimateOrcAvgWidthVisitor`。

## 4. 核心设计思想

### 4.1 Schema 双向映射与字段 ID 兼容
ORC 不原生支持字段 ID。模块通过命名约定（`IdToOrcName`）把 Iceberg 字段 ID 编码进 ORC 列名，配合 `ApplyNameMapping`/`HasIds`/`RemoveIds` 在读写时恢复 ID 语义，保证 Iceberg 的 Schema 演进能力在 ORC 上仍成立。

### 4.2 访问者模式遍历类型树
`OrcSchemaVisitor`/`OrcSchemaWithTypeVisitor`/`OrcToIcebergVisitor` 用访问者模式统一遍历 Iceberg/ORC 类型树，把转换逻辑解耦为可组合的访问步骤，便于扩展新类型。

### 4.3 向量化读写
读取侧以 `VectorizedRowBatch` 为单位批量读取（`OrcBatchReader`/`VectorizedRowBatchIterator`），写入侧把值填入 ORC 向量（`OrcValueWriter`），发挥列式格式的向量化性能优势。

### 4.4 谓词下推
`ExpressionToSearchArgument` 把 Iceberg 表达式翻译为 ORC 原生 `SearchArgument`，让 ORC 在读取时跳过不匹配的 row group，减少 IO。

### 4.5 统一 Builder 入口
`ORC.java` 用 Builder 模式统一数据/删除文件的读写构建，配置（Schema/分区/加密/压缩/指标模式）链式注入，与 Iceberg 读写抽象对齐。

## 5. 上下游依赖关系

- **向上**：实现 core 的 `FileAppender`/读取器/指标接口，被 core 与 data/spark/flink 等按格式选用。
- **向下**：依赖 Apache ORC SDK 与 Hadoop FileSystem。
- **横向**：与 `iceberg-parquet`/`iceberg-arrow`(读 Parquet) 同属格式集成层，互为平行实现。

## 6. 设计要点总结

1. **字段 ID 兼容**：以命名约定 + NameMapping 弥补 ORC 无原生 ID。
2. **访问者模式**：类型树转换解耦可扩展。
3. **向量化**：批量读写发挥列式性能。
4. **谓词下推**：表达式→SearchArgument 减少 IO。
5. **统一 Builder**：与 Iceberg 读写抽象对齐。

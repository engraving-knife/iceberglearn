# Iceberg Arrow 模块架构与设计思路

> 源码路径：`arrow/src/main/java/org/apache/iceberg/arrow/`
> 模块工件：`iceberg-arrow`

## 1. 模块定位

`iceberg-arrow` 是 Iceberg 扫描执行层与 Apache Arrow 列式内存模型之间的**桥接层**。在 Iceberg 整体架构中，它位于扫描任务规划（`iceberg-core` 的 `TableScan`/`CombinedScanTask`）与计算引擎（Spark / Flink）之间，承担以下职责：

- 将 Parquet 文件中的列式数据**向量化**地读取到 Arrow 的堆外内存向量中，以批次（batch）形式对外输出。
- 在 Iceberg 类型系统与 Arrow 类型系统之间做 Schema 转换与类型映射。
- 管理 Arrow 内存分配器（`RootAllocator`）的生命周期，统一向量内存的申请与释放。
- 处理字典编码数据的解码、空值（nullability）追踪、元数据列（常量列/行位置/删除标记）等读取语义。

该模块专注于**读取**（无写入能力），且当前仅支持 Parquet 格式作为底层数据源。它实现了 `iceberg-parquet` 模块定义的 `VectorizedReader` 接口，是向量化读取链路的"下半段"——上半段（行组过滤、页源管理、批次调度）由 `iceberg-parquet` 的 `VectorizedParquetReader` 完成。

## 2. 包结构概览

本模块包含三个包：

### 2.1 `org.apache.iceberg.arrow`（顶层包）

| 类 | 职责 |
|----|------|
| `ArrowSchemaUtil` | Iceberg `Schema` 与 Arrow `Schema` 的双向转换，含类型映射与 Map 语义标记 |
| `ArrowAllocation` | 全局共享的 Arrow `RootAllocator` 持有者（静态单例，上限 `Long.MAX_VALUE`） |
| `DictEncodedArrowConverter` | 将字典编码的 Arrow 向量解码为强类型 Arrow 向量（Decimal/Timestamp/Long/Float/Double/String/Binary/Time） |

### 2.2 `org.apache.iceberg.arrow.vectorized`（向量化读取基础设施）

| 类 | 职责 |
|----|------|
| `ArrowReader` | 扫描级读取入口，接收 `CombinedScanTask`，逐文件以 Parquet 向量化方式产出 `ColumnarBatch` |
| `VectorizedTableScanIterable` | `ArrowReader` 的便捷封装，提供默认批大小（2^16）与开箱即用配置 |
| `BaseBatchReader<T>` | 批读取器抽象基类，持有按列排列的 `VectorizedArrowReader` 数组与 `VectorHolder` 数组，提供行组信息下发/批大小设置/向量关闭等公共逻辑 |
| `ArrowBatchReader` | 继承 `BaseBatchReader`，逐列调用读取器填充向量并组装为 `ColumnarBatch`（`read` 方法为 final） |
| `VectorizedArrowReader` | 单列向量化读取器，实现 `VectorizedReader<VectorHolder>`，委托 `VectorizedColumnIterator` 逐页解码并写入 Arrow 向量 |
| `VectorizedReaderBuilder` | 继承 `TypeWithSchemaVisitor`，按字段 ID 将 Parquet 列读取器重排为 Iceberg schema 顺序，处理元数据列 |
| `VectorHolder` | 单列 Arrow 向量及其读取上下文（列描述符/字典/空值持有者/Iceberg 字段）的容器，含常量/删除/位置等专用子类 |
| `NullabilityHolder` | 按行下标追踪空值状态的轻量持有器（字节数组 + 区间批量设置） |
| `ColumnarBatch` | 列式批次容器，包装一组 `ColumnVector`（借鉴 Spark），可转为 `VectorSchemaRoot` |
| `ColumnVector` | 单列访问器，包装 `VectorHolder` 与 `ArrowVectorAccessor`，提供按行读取并处理空值 |
| `ArrowVectorAccessor` | Arrow 向量值访问器基类（模板方法模式），按行读取各类值，泛型适配不同引擎的 Decimal/字符串表示 |
| `ArrowVectorAccessors` | 访问器工厂，按向量类型创建具体 accessor |
| `GenericArrowVectorAccessorFactory` | 泛型化的类型化访问器生成工厂，支持 Decimal/UTF8String/Array/Struct 的引擎适配 |

### 2.3 `org.apache.iceberg.arrow.vectorized.parquet`（Parquet 向量化解码层）

| 类 | 职责 |
|----|------|
| `VectorizedColumnIterator` | 列迭代器的向量化版本，继承 `BaseColumnIterator`，按批次读取行组内某列的数据页，委托 `VectorizedPageIterator` |
| `VectorizedPageIterator` | Parquet 数据页的向量化迭代器，继承 `BasePageIterator`，按字典解码模式（NONE/LAZY/EAGER）分发批量解码 |
| `BaseVectorizedParquetValuesReader` | 向量化解码器基类 |
| `VectorizedDictionaryEncodedParquetValuesReader` | 字典编码数据的向量化解码器，将字典 ID 解码为实际值写入 Arrow 向量 |
| `VectorizedParquetDefinitionLevelReader` | definition level 的向量化读取器，批量判定空值 |
| `DecimalVectorUtil` | Decimal 向量写入工具 |

## 3. 核心类与设计模式

### 3.1 模板方法模式：批读取器层级

```
VectorizedReader<T> (接口, 定义于 iceberg-parquet)
        ▲
        │ implements
BaseBatchReader<T> (抽象基类: 持有 readers[]/vectorHolders[], 公共 setRowGroupInfo/setBatchSize/close)
        ▲
        │ extends
ArrowBatchReader (final read(): 逐列填充 → 组装 ColumnarBatch)
```

`BaseBatchReader` 把"按列分发"的模板逻辑下沉到基类（`setRowGroupInfo`/`setBatchSize`/`close` 逐列转发），子类只需实现具体的 `read` 组装逻辑。`ArrowBatchReader.read()` 标记为 `final`，固定批读取流程，保证向量与行数一致性。字段以 `protected` 暴露给同包子类以减少访问器开销。

### 3.2 策略与枚举分派：`VectorizedArrowReader`

`VectorizedArrowReader` 是单列读取的核心，实现 `VectorizedReader<VectorHolder>`：

- **`ReadType` 枚举分派**：用 `FIXED_LENGTH_DECIMAL`/`INT_BACKED_DECIMAL`/`VARCHAR`/`INT`/`LONG`/`DICTIONARY` 等枚举值替代运行期反射，按类型选择写入路径。
- **空对象模式**：提供 `NullReader`/`ConstantVectorReader`/`PositionVectorReader`/`DeletedVectorReader` 等内部子类，以统一接口表示不实际读文件的元数据列。
- **字典编码判定**：`producesDictionaryEncodedVector` 标记向量是否字典编码。当 Parquet 回退到普通编码时，即使存在字典也会提前解码（EAGER 模式），故向量是否字典编码以此标志为准。

### 3.3 访问者模式：`VectorizedReaderBuilder`

`VectorizedReaderBuilder` 继承自 `iceberg-parquet` 的 `TypeWithSchemaVisitor<VectorizedReader<?>>`，复用 schema 联合遍历框架：
- 按 Parquet 字段 ID 建立 `VectorizedArrowReader` 映射。
- 遍历 Iceberg 字段，依次处理常量列、行位置列、删除标记列，其余按 ID 取对应读取器，缺失则用 `nulls()` 占位。
- 通过注入的 `readerFactory`（如 `ArrowBatchReader::new`）由列读取器列表组装批读取器。
- **设计意图**：解耦 schema 遍历与读取器构造，`readerFactory` 注入允许上层自定义批读取器类型。

### 3.4 容器与空对象模式：`VectorHolder`

`VectorHolder` 把单列的 Arrow 向量与其读取上下文（列描述符、字典、空值持有者、Iceberg 字段定义）打包传递，避免散落多处状态：
- `ConstantVectorHolder<T>`：常量列持有者，不实际产出向量值，消费者使用 `constantValue` 填充。
- `PositionVectorHolder`：行位置列持有者。
- `DeletedVectorHolder`：删除标记列（`IS_DELETED`）持有者。
- `dummyHolder()`：占位持有者（向量为 null）。
- **设计意图**：通过子类以空对象方式表示不实际读文件的元数据列，使读取流程统一处理。

### 3.5 模板方法模式：`ArrowVectorAccessor`

`ArrowVectorAccessor<DecimalT, Utf8StringT, ArrayT, ChildVectorT>` 是向量值访问器基类：
- 各 `getXxx` 方法默认抛 `UnsupportedOperationException`，由具体子类只覆写其支持的方法。
- 泛型参数 `DecimalT`/`Utf8StringT`/`ArrayT`/`ChildVectorT` 使访问器能适配不同引擎的类型表示（如 Spark 的 `UTF8String`、Hive 的 `HiveDecimal`）。
- 由 `GenericArrowVectorAccessorFactory` 通过反射生成具体子类实例。

### 3.6 单例模式：`ArrowAllocation`

`ArrowAllocation` 通过静态初始化块创建全局唯一的 `RootAllocator`（上限 `Long.MAX_VALUE`），保证线程安全的单例创建。集中持有分配器避免各处自行创建导致内存难以统一回收。

## 4. 关键流程

### 4.1 扫描级读取流程

```
TableScan  →  ArrowReader(scan, batchSize, reuseContainers)
        │  open(tasks)
        ▼
VectorizedCombinedScanIterator  (内部迭代器)
        │
        ├── 构造期: 展平 CombinedScanTask → FileScanTask 列表
        │           校验: 无 delete 文件 / 至少一列 / 类型受支持(SUPPORTED_TYPES)
        │           批量解密输入文件 → inputFiles 映射 (减少密钥服务器 RPC)
        │
        ▼  hasNext() / next()
逐文件迭代:
        │  open(FileScanTask)
        ▼
Parquet.read(location)
    .project(expectedSchema)
    .split(task.start(), task.length())
    .createBatchedReaderFunc(fileSchema → buildReader(...))   ← 构造 ArrowBatchReader
    .recordsPerBatch(batchSize)
    .filter(task.residual())
    .build()  →  VectorizedParquetReader  (来自 iceberg-parquet)
        │  iterator()
        ▼
VectorizedParquetReader.FileIterator  (逐行组、逐批次调度)
        │  next()
        ▼
ArrowBatchReader.read(reuse, numRowsToRead)
```

### 4.2 批读取流程

```
ArrowBatchReader.read(reuse, numRowsToRead)
        │  (reuse == null 时先 closeVectors() 清理旧向量)
        ▼
逐列 i:
    vectorHolders[i] = readers[i].read(vectorHolders[i], numRowsToRead)
        │
        ▼  VectorizedArrowReader.read()
    分配/复用 Arrow 向量 (按 ReadType 选择向量类型)
    委托 VectorizedColumnIterator.nextBatch(vec, numRowsToRead)
        │
        ▼  VectorizedColumnIterator.nextBatchOf()
    VectorizedPageIterator 批量解码:
        ├── DictionaryDecodeMode.NONE  → plain 编码批量读取
        ├── DictionaryDecodeMode.LAZY  → 产出字典编码向量 (IntVector 存字典 ID)
        └── DictionaryDecodeMode.EAGER → 提前解码字典值写入强类型向量
    NullabilityHolder 记录空值位置
        │
        ▼  返回 VectorHolder
    校验 numRowsInVector == numRowsToRead
    columnVectors[i] = new ColumnVector(vectorHolders[i])
        │
        ▼
return new ColumnarBatch(numRowsToRead, columnVectors)
```

### 4.3 构建读取器流程

```
ArrowReader.buildReader(expectedSchema, fileSchema, setArrowValidityVector)
        │
        ▼
TypeWithSchemaVisitor.visit(expectedSchema.asStruct(), fileSchema,
    new VectorizedReaderBuilder(expectedSchema, fileSchema, setArrowValidityVector,
        ImmutableMap.of(), ArrowBatchReader::new))
        │
        ▼  VectorizedReaderBuilder.message()
    按 Parquet 字段 ID 建立读取器映射
    遍历 Iceberg 字段:
        ├── 常量列 → ConstantVectorReader
        ├── 行位置列 (_pos) → PositionVectorReader
        ├── 删除标记列 (IS_DELETED) → DeletedVectorReader
        ├── 普通 primitive 列 → new VectorizedArrowReader(desc, field, alloc, setValidity)
        └── 缺失列 → nulls() 占位
    readerFactory.apply(readers) → ArrowBatchReader
```

### 4.4 字典解码流程

`VectorizedPageIterator` 根据行组编码情况选择解码模式：

- **NONE**（plain 编码）：直接用 `plainValuesReader` 批量读取原始值写入向量。
- **LAZY**（全部字典编码）：产出字典编码向量（`IntVector` 存字典 ID + 持有 `Dictionary`），延迟到下游需要时再解码。`ColumnVector.getArrowVector()` 通过 `DictEncodedArrowConverter` 按需物化为强类型向量。
- **EAGER**（字典回退到 plain）：通过 `VectorizedDictionaryEncodedParquetValuesReader` 提前解码字典值，写入强类型向量。

## 5. 与其他模块的关系

### 5.1 依赖的模块

- **iceberg-core**：`Schema`/`Types`、`TableScan`/`CombinedScanTask`/`FileScanTask`、`FileIO`、`EncryptionManager`/`EncryptedFiles`、`MetadataColumns`（`ROW_POSITION`/`IS_DELETED`）、`NameMappingParser`、`TableScanUtil`、`ExceptionUtil`。
- **iceberg-parquet**（强依赖）：
  - `Parquet`（读写入口，`ArrowReader.open()` 调用 `Parquet.read()`）
  - `VectorizedReader`（向量化读取器接口，本模块实现）
  - `VectorizedParquetReader`（向量化调度器，由 `Parquet.read().createBatchedReaderFunc()` 触发）
  - `TypeWithSchemaVisitor`（schema 联合遍历基类，`VectorizedReaderBuilder` 继承）
  - `BaseColumnIterator`/`BasePageIterator`（列/页迭代器基类，向量化版本继承）
  - `ParquetUtil`（字典读取等工具）、`ValuesAsBytesReader`（plain 值读取）
- **Apache Arrow**：`RootAllocator`/`BufferAllocator`（内存分配）、各类向量（`IntVector`/`BigIntVector`/`VarCharVector`/`DecimalVector`/`TimeStampMicroTZVector` 等）、`VectorSchemaRoot`、`NullCheckingForGet`。
- **parquet-mr**（间接，通过 iceberg-parquet）：`ColumnDescriptor`/`Dictionary`/`ColumnChunkMetaData`/`PageReadStore`/schema 类型。

### 5.2 被依赖的模块

- **iceberg-spark / iceberg-flink**：各引擎的向量化读取集成层调用 `ArrowReader` 或 `VectorizedTableScanIterable` 获取列式批次，再转换为引擎内部的列式结构（如 Spark 的 `ColumnarBatch`/`ColumnVector`）。
- **iceberg-data**（部分场景）：通用数据模型的向量化读取。

## 6. 设计亮点与权衡

### 6.1 复用 iceberg-parquet 的向量化骨架

本模块不重复实现行组过滤、页源管理、批次调度，而是复用 `iceberg-parquet` 的 `VectorizedParquetReader` 与 `ReadConf`：
- `iceberg-parquet` 定义 `VectorizedReader` 接口与 `VectorizedParquetReader` 调度器。
- `iceberg-arrow` 提供 `VectorizedReader` 的 Arrow 实现（`VectorizedArrowReader`/`ArrowBatchReader`）。
- 通过 `Parquet.read().createBatchedReaderFunc()` 注入 Arrow 实现完成对接。
- **权衡**：两个模块存在交叉依赖与共享基类（`BaseColumnIterator`/`BasePageIterator`），边界略模糊，但避免了向量化调度逻辑的重复实现。

### 6.2 LAZY 与 EAGER 字典解码的权衡

`VectorizedPageIterator` 支持三种字典解码模式：
- **LAZY**：全部字典编码时产出字典编码向量（`IntVector` + `Dictionary`），延迟解码到下游真正需要时。减少解码开销，但要求下游能处理字典编码形态。
- **EAGER**：字典回退到 plain 编码时提前解码，简化下游处理。
- **权衡**：LAZY 模式性能更优但增加下游复杂度（需通过 `DictEncodedArrowConverter` 物化）；EAGER 模式简单但有解码开销。`ColumnVector.getArrowVector()` 与 `getFieldVector()` 提供两种访问方式，分别返回解码后与原始向量。

### 6.3 空对象模式统一元数据列处理

`VectorHolder` 通过 `ConstantVectorHolder`/`DeletedVectorHolder`/`PositionVectorHolder`/`dummyHolder` 等子类，以空对象方式表示不实际读文件的元数据列（常量列、`_pos`、`IS_DELETED`）：
- 这些列的读取器（`ConstantVectorReader`/`PositionVectorReader`/`DeletedVectorReader`）不持有 `ColumnDescriptor` 与 `VectorizedColumnIterator`，`read()` 直接返回对应持有者。
- **权衡**：使批读取流程对元数据列与普通列一视同仁，无需特殊分支，但 `VectorHolder` 的字段允许 null（dummy 持有者），需调用方判空。

### 6.4 泛型访问器适配多引擎

`ArrowVectorAccessor` 与 `GenericArrowVectorAccessorFactory` 通过泛型参数（`DecimalT`/`Utf8StringT`/`ArrayT`/`ChildVectorT`）适配不同引擎的类型表示：
- Spark 可映射为 `UTF8String`/`Decimal`/`ColumnarArray`/`ArrowColumnVector`。
- Hive 可映射为 `HiveDecimal`/Java `String`。
- **权衡**：泛型 + 反射工厂增加了初始构造开销，但实现了访问器与引擎类型的解耦，避免为每个引擎重写列访问逻辑。

### 6.5 全局 Allocator 与内存管理

`ArrowAllocation` 持有全局 `RootAllocator`（上限 `Long.MAX_VALUE`），`VectorizedReaderBuilder` 创建子分配器供读取器使用：
- 向量内存纳入 Arrow 的引用计数管理，`ColumnarBatch`/`BaseBatchReader` 实现 `AutoCloseable`/`close()` 确保释放。
- `reuseContainers` 选项允许在迭代中复用 Arrow 向量以减少内存分配，但调用方需在使用或深拷贝后再获取下一批。
- **权衡**：全局不设限的 Allocator 简化了使用，但内存控制交由上游框架负责；若上游未控制好可能导致堆外内存溢出。

### 6.6 当前限制

模块文档与代码中标注了已知限制：
- 不支持 delete 文件（`hasDeletes` 时直接抛 `UnsupportedOperationException`）。
- 不支持嵌套类型（List/Map/Struct），`VectorizedColumnIterator` 校验 `maxRepetitionLevel == 0`。
- 类型提升未完全对齐最新 Schema。
- 常量列以字典编码返回 int32。
- 仅支持 Parquet 格式，不支持 ORC/Avro 的向量化读取。
- **权衡**：以受限的类型支持换取了向量化读取的高性能，复杂类型场景回退到 `iceberg-parquet` 的逐行路径。
